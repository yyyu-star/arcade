# 《开盘》实盘模式设计（筹码体系第 2 步）

> 2026-10-15。依据总仓库 `docs/economy.md`（以 main 为准）和维护者当天的决定：实盘打半年、账单按平时的 25%、四档对应难度 1–4；
> "输了丢着不结，等到期原样退回"这条缺口接受、不堵。0.6.0 已照本稿实现，之后 0.6.5（战绩小结、错误对照）、0.6.8（桌上另有一份不拦开局）改过的地方都写回了本稿。
> 文中的数字都是模拟实测（2026-10-15，开盘 0.5.12，真实行情、仓位 / 押跌 / 抵押都开），时长一节另有说明哪些是推断。
> **0.10.0（2026-10-16）配平**：一局改成 5 个月；各档有自己的账单倍数和"涨跌倍数"（资产涨跌放大几倍算进筹码）；豪华档改用难度 3。
> 目标是仓库根 `docs/balance.md`，实测和取舍见 [design-balance.md](design-balance.md)。本稿第 0–5 节已按 0.10.0 改，第 3.1 节和第 8 节是 0.6.0 的过程，留作来历。

## 0. 对照约束

| 约束（`economy.md`） | 做法 |
|---|---|
| 娱乐模式原样保留、不碰钱包 | 现在的玩法（新游戏、快速开始、每日挑战）一点不改；实盘是开始菜单里多出来的一个入口（第 4 节） |
| 带一份当本金，按"最终资产 ÷ 初始资产"结回，最多 3 倍，破产为 0 | 公式照用，0.10.0 起资产的涨跌按档位放大几倍再算（第 2.2 节）；实盘一局 5 个月、账单按档打折（第 1 节，原因见 3.1 和 design-balance.md） |
| 最多输一份、永远不欠 | 结回 ≥ 0；借款在结算时先还掉，还不上的部分只会让结回变成 0，不会变成负数 |
| 同一档一场的输赢在一份左右 | 实测各档九成以上的局结回在 0–2 份之间（3.3） |
| 一场 15–25 分钟（`balance.md`） | 5 个月 25 个交易日，按每步耗时估约 15 分钟，看得仔细的人 20 分钟上下（3.2） |
| 越往上越难，小档认真玩能赚 | 小 / 中 / 大 / 豪华 四档逐档变难，小白、普通两种打法的每场期望都落在 `balance.md` 第 2 节的区间里（design-balance.md） |
| 快乐为主、不诱导 | 输了说安慰话、提明天的补给；不说"回本"，不催、不倒计时（第 5 节） |
| 钱包只经游戏的服务端调，`mode: client` | 开盘的 Worker 加三条接口，经 `WALLET` 服务绑定转给平台钱包的 `buyin` / `settle` / `refund`（第 6 节，按平台钱包的接口对齐） |

## 1. 一局实盘长什么样

- **5 个月**（0.10.0 前是半年）：只打 1–5 月（每月 5 个交易日，共 25 天）。5 月底还完那个月的账单就结束，进结算。月度主题、看点卡、三选一、事件、第 4 个月的中场关都照旧，
  第 8 个月的中场关自然没有。
- **账单打折**：常规月供和突发账单都乘这一档的账单倍数（`BALANCE.live.tiers`，现在小档 0.17、中档和大档 0.18、豪华档 0.22；难度自带的倍数照样叠加）。
  说法："实盘是拿闲钱炒几个月，家里的开销不压在这笔钱上，每月只交一点生活费。"
- **涨跌倍数**（0.10.0）：资产的涨跌放大几倍算进筹码，小档 2.8、中档 3.5、大档 4、豪华档 5（2.2）。几个月里资产的起伏本来只有一两成，
  不放大的话会玩和不会玩的只差零点几成，"认真玩能赚"体会不到；越往上放得越大，赢输都更刺激。
- **难度由档位定**（不需要先在娱乐模式里解锁那一级）：

| 档位 | 一份 | 难度 | 这一档多了什么（难度逐级叠加，上一档的都带着） |
|---|---|---|---|
| 小 `small` | 2,000 | 1 新手 | 要还的钱最少 |
| 中 `mid` | 10,000 | 2 普通 | 群里一半的消息是瞎传的，月供多一点 |
| 大 `big` | 50,000 | 3 高手 | 每次买入要交手续费 |
| 豪华 `lux` | 200,000 | 3 高手 | 和大档同一套行情，生活费更高、涨跌倍数更大 |

  另外每高一级，所有群友的准确率还会 −0.02（现有规则，`BALANCE.intel.diffStep`），所以"越往上消息越真假难辨"是两层叠加。
  豪华档 0.10.0 前用难度 4（消息失真）：那一级群里八成消息是瞎传的，会看战绩的人几乎没了优势，小白和普通打法只差 0.03 份，
  要拉开到目标得把涨跌放大六倍以上；改用难度 3、靠生活费和涨跌倍数变难。0.10.0 前开的局开局设置里没记档位，按难度认（4 = 豪华档），结算照旧。
- **人设随便选**（已解锁的都行）：实测几个人设在实盘下的结果差不多（0.6.0 时实测，小档简单打法平均结回，每个 270 局：新手 1.07、退休 1.06、宝妈 1.10、码农 1.04、游资 1.07），不另外限制。
- 其余全照旧：真实行情按种子随机抽一段、个股照搬真实走势、群聊、道具、仓位 / 押跌 / 抵押。

## 2. 进场、结算、中途退出

### 2.1 筹码和游戏里的钱怎么换算

游戏里照旧用"元"（开局账户按人设，新手 10 万），股价、账单、事件的数字都不变，不然文案和手感全得重做。筹码只是一个比例：

> 现在值多少筹码 = 一份 × 当前资产 ÷ 开局资产

顶栏多一个小牌子"实盘 · 小档 2,000 → 现在约 2,104"，跟着每天收盘更新。开局资产在开局那一刻定下（人设的开局账户），之后的月度奖励、事件给的钱都算赚到的。

### 2.2 结算

- **当前资产** = 账户（持仓按最近一次收盘算，押跌按当前盈亏算，这些现在就都在账户里）− 还没还的借款。
- **倍数** = 1 + 涨跌倍数 ×（当前资产 ÷ 开局资产 − 1），最低 0，最高 3。涨跌倍数开局时抄进这局的设置（`live.lev`），之后改默认值不影响已经开了的局；
  0.10.0 前开的局没有这一项，按 1 算（就是原来的"当前资产 ÷ 开局资产"）。
- **结回** = 一份 × 倍数，向下取整到 1 筹码。最多结回 3 份，也就是最多净赢 2 份。
- **破产**（某个月的账单交不上，现有规则里的"没撑到最后"）：结回 0。资产跌掉 1 ÷ 涨跌倍数（小档约 36%、豪华档 20%）也是 0。
- 打完、中途退出、破产，都按这一个公式结。

### 2.3 中途退出

- **还没开始**：选完档位、带入以后，第一个交易日还没开盘（没有任何一天的涨跌结果）就退出 → 用 `refund`，那一份原样退回。
  这是 `refund` 唯一的用处。
- **开始以后**：一律按当前资产结（2.2）。入口在设置里的「提前收手」，点了先确认一次："按现在的资产结算：约 2,104 筹码。这局就到这里了。"
- **回大厅、刷新、关页面、断网都不算退出**：这局照常存着，回来接着打完再结（2.4）。所以回大厅的确认框在实盘局里改成："这局实盘会存着，回来接着打完再结算。"

### 2.4 刷新、断网、关页面之后

- **一局的进度**：和现在一样，每一步都存在本机的 `kaipan.save`。实盘的规则（几个月、账单倍数、涨跌倍数、档位）写在这局的开局设置里，存档自带，读档后照样是实盘。
- **实盘的账**：另存一条 `kaipan.live`（本机，`src/platform/live.ts`）：`{ ref, tier, stake, seed, at, until, step, kind?, bp?, stats?, credited?, capped?, error?, wait?, told?, user? }`，
  `step` 是 `buying`（带入发出去了、还没等到回话）→ `playing` → `settling`（结回或放弃发出去了、还没结上）→ `done`，或者 `void`（不算筹码了）、`error`（开盘自己的 bug）。
  `ref` 是带入前浏览器生成的随机 id（`kaipan-<uuid>`），钱包里桌上那一份也记着它；`seed` 用来认存档里是不是这一局。
  - 带入前先记成 `buying` 再发：回话丢了（断网、关页面）的话那一份可能已经扣了，下次打开实盘面板或再带入之前先用 `refund` 把这个 `ref` 收回来
    （没带入成的，钱包回 `no_stake`，直接清掉）。不收回的话那一份放到 24 小时到期原样退回；期间照样能开新的一局，开局面板会提示还有一份没结，可以回去接着打或原样退回（0.6.8，见下文）。
  - `user` 是带入的账号（Worker 带入成功时回给浏览器）。结回、放弃时带上，现在登录的不是他，Worker 回 409 `wrong_user`、不碰钱包，
    记录停在 `settling` 等那个账号登录回来；不然会拿新账号去结，钱包回 `no_stake`，这局就白白作废了。
  - 几个标签页共用这一条：每次看、每次改之前都重读存储；存储里已经是另一局、还没结完时不覆盖。
  - 打开游戏时记录是 `playing`、存档里却不是这一局（带入后还没开局就关了页面，或者存档没了）：这局没打成，按 `refund` 原样退回。
- **回来时**：开始菜单读到 `kaipan.live` 是 `playing` 且没过 `until`，「继续」按钮写"继续 · 实盘 3月"，接着打。
- **断网**：打的时候不用联网。只有带入和结回要联网：
  - 带入连不上 → 不开局，提示"钱包暂时连不上，可以先玩娱乐模式"；
  - 结回连不上 → `kaipan.live` 停在 `settling`，结算页写"成绩记下了，联网后自动结回"；之后每次打开、回到前台、联网时重试。重复的结回钱包只算一次（操作 id 固定，见第 6 节）。
- **超过 24 小时**：`until` 是带入时间 + 24 小时（钱包允许的最长期限）。过了期限钱包会把那一份原样退回，之后再来结回会被拒。
  游戏这边：`kaipan.live` 过期时，这局改成娱乐局继续（"这局放了超过一天，本金已经原样退回钱包；可以接着玩，但不再算筹码"）。
  一局估计 15–20 分钟，正常玩不会碰到。
- **换了设备**：进行中的局只在开局那台设备上（一局里的进度本来就不同步）。另一台设备的开局面板能从钱包（`GET /api/wallet`）看到开盘桌上别处的几份。
  0.6.8 起（平台 0.9.5 起同一游戏可以同时有好几份；设计上不加没必要的限制）**不再因此拦着开新局**：左下角写
  "你还有一局实盘没结（x 筹码）"，给「回去接着打」（说明回那台设备点「继续」）和「原样退回」（先确认，再对那一份调 `refund`）。
  原样退回只是把 2.5 里"放一天自动原样退回"提前，不是新的缺口。这台设备自己正在结的那份（`settling` / `buying`）仍然要等它结完。
- **同一时间只有一局**：实盘局没结完时，「新游戏」「快速开始」「每日挑战」都会先问"实盘这局还没打完：继续 / 提前收手"，不会悄悄覆盖。
  反过来，娱乐局打到一半去开实盘，照现在的"放弃当前这局？"确认。

### 2.5 已知缺口（接受，不堵）

开局后一直不结，等 24 小时到期，那一份会原样退回。输了的局丢着不管就能拿回本金。这条接受、不堵：排行榜和实盘的取向是只防刷额度、不防作弊；
client 模式每天每个游戏的净赢有上限（钱包管，份数是平台的设置，现在默认 10 份），这条路刷不崩整个体系。我们只保证正常玩家不会无意中走到这条路：刷新、断网、关页面后能接着打完再结（2.4），
开始之后的退出一律按当前资产结（2.3）。

### 2.6 杠杆（0.11.0）

开局在档位卡下面三选一：稳健 1×（默认）、进取 2×、疯狂 3×。只给实盘，娱乐和每日挑战没有。

- **结回倍数** = 1 + 杠杆 ×（2.2 算出的档位倍数 − 1），最低 0；封顶 1× 3 倍、2× 5 倍、3× 7 倍。最多输掉这一份不变。
- **利息**：开了 2×、3× 每月账单里多一笔「开了杠杆，这个月借钱的利息」，越高越多（`BALANCE.live.gears[].interest` × 开局资产 ÷ 档位涨跌倍数）。
  再按档位打折（`gearRate`：小档 1、中档 0.5、大档和豪华档 0.25）：越往上的档本来就越难，同样的利息会把杠杆压成纯亏。
- **清零线**：每天收盘后、月底交完账单后，放大后的结回倍数跌到清零线（2× 0.2 份、3× 0.1 份）就强制结束，这局按 0 结（`endReason: 'margin'`）。
  放大后跌到 0.3 份以内的那几天，顶栏的资产变红闪、盘前提醒一句（`warnGap`）。
- 杠杆、封顶、利息、清零线开局时抄进这局的设置（`live.gear`），之后改默认值不影响已经开了的局；稳健 1× 不写这一项，和 0.10.0 的局一模一样。
- 钱包不用改：平台按「最多结回带入 + 余量」收，开盘的 Worker 按 `LIVE_MAX_BP`（7 倍）挡超出的数。
- 实测和取舍见 `design-balance.md` 4.4。

## 3. 尺度对齐（实测）

**怎么量的**：`tools/bots.ts` 里的机器人，真实行情，135 段均匀覆盖，仓位、押跌、抵押都开，新手人设。规则核心自己支持实盘（`RunSetup.live`），
`npm run sim -- --live` 出下面 3.3 的表（`tools/live.ts`），`npm run sim -- --balance` 出小白、普通对照 `balance.md` 目标的表（见 [design-balance.md](design-balance.md)）。
`tests/live-sim.test.ts` 每档跑 135 局锁住形状，数值改动后这几张表要重新量。

机器人代表的打法：

| 机器人 | 代表 |
|---|---|
| `xiaobai` | **小白**（0.10.0，`balance.md` 第 1 节）：追最热的题材、谁说涨都信、说跌就卖，不止损 |
| `normal` / `putong` | **普通**：简单合理的打法，看群友战绩、升温早期买、过热看空就卖、亏两成割肉 |
| `truster` | 只听战绩好的群友 |
| `smart` | 认真推断风口阶段和群友可信度 |
| `random` | 乱买乱卖 |
| `follower` | 无脑买推荐、从不卖 |
| `heavy` | 一律重仓、赚了就加仓 |
| `gambler` | 能抵押的都押去借钱 |

### 3.1 为什么不能直接用"一年、全额账单"（0.6.0 时）

现在的开盘是"撑过一年的账单"：一年的账单加起来约 20 万，开局只有 10 万，通关的人最后账户通常只剩开局的一两成。直接按"最终资产 ÷ 初始资产"结，
第 1 级（每格 270 局）：

| 打法 | 通关率 | 平均结回（份） | 结回 0 的局 |
|---|---|---|---|
| 乱买乱卖 | 3% | 0.00 | 97% |
| 简单打法 | 37% | 0.07 | 66% |
| 会玩的 | 65% | 0.25 | 37% |

几乎人人输光，完全不符合"小档简单打法小赚"。试过的几种组合（第 1 级，简单打法平均结回）：一年 + 账单 50% 是 0.73、一年 + 25% 是 1.23（但时长超了，3.2）、
半年 + 全额 0.55、半年 + 50% 0.90、**半年 + 25% 1.07**（270 局）。半年 + 25% 既在时长里，梯度也对，定了这一组。

0.10.0 配平时又改了一次：0.6.0 的"半年 + 25%"下普通打法只比小白多赚 0.09 份、小档中位数 1.04，离 `balance.md` 的"认真玩能赚"差得远，
而且试玩的反馈是"花很长时间、收益率不高、难度还很高"。改成 5 个月、各档自己的账单倍数，再把资产的涨跌按档放大，过程和取舍见 design-balance.md 第 3 节。

### 3.2 时长

- **自动试玩的下限**（0.6.0 时量的）：`npm run shot -- --v05 --l1`（动画开着、1 倍速、真实鼠标键盘，但每一步不思考）打完一年 58 个交易日、41 个弹窗，用了 **780 秒**，
  拆成每个交易日约 11 秒、每个弹窗约 3.5 秒。
- **真人的估法**（0.10.0，`tools/live.ts` 的 `STEP_SECONDS`，模拟器按机器人每局实际做了什么一步步加）：在下限上加思考，每个交易日看群聊和推荐 15 秒、
  每次买卖 3 秒、每个弹窗读 4 秒、月底三选一多想 10 秒，开局和结算共 30 秒。这些是推断，没有真人计时校准过。
- **结果**：实盘 5 个月（25 个交易日）约 **15 分钟**；娱乐 12 个月约 **34 分钟**。看得仔细的人更久，所以画面上写"约 15–20 分钟""约 30–40 分钟"。
  0.6.0 的半年按同样的估法约 18 分钟，试玩仍觉得长，说明估法偏乐观；缩到 5 个月给慢一点的玩家留了余地。

### 3.3 各档结果（0.10.0：5 个月，每格 540 局，种子 `live6-*`）

结回是"份"：1 = 不赚不亏，0 = 输光一份，3 = 封顶。±后面是标准误。

| 档位 | 打法 | 平均结回 | 赚的局 | 10% / 50% / 90% 分位 | 结回 0 | 在 0–2 份内 |
|---|---|---|---|---|---|---|
| 小 | 普通 `normal` | **1.325 ± 0.019** | 78% | 0.83 / 1.30 / 1.90 | 0% | 92% |
| | 信靠谱群友 `truster` | 1.210 ± 0.024 | 63% | 0.55 / 1.16 / 1.91 | 0.7% | 92% |
| | 会推断的 `smart` | 1.227 ± 0.024 | 64% | 0.55 / 1.17 / 1.92 | 0.6% | 93% |

## 6. 钱包怎么调

按平台已经上线的钱包（总仓库 `docs/platform-backend.md` 5.9、15.9）写。

- **路径**：浏览器 → 开盘的 Worker（同域 `POST /games/kaipan/api/live/{buyin,settle,refund}`，带 `X-Arcade: 1`）→ 服务绑定 `WALLET` 的钱包 RPC。
  浏览器从来不直接碰带入、结回、放弃（平台的 `/api` 里也没有这几条路）。`wrangler.jsonc` 的 `run_worker_first` 加上 `/games/kaipan/api/*`。
- **绑定**：和登录闸门用的 `ARCADE`（fetch 绑定）分开。0.8.0 起模块的 `wrangler.jsonc` 是不带平台的独立配置，这条绑定由部署工具（`tools/deployer`）在本站部署时补上；单独部署没有它，三条接口回 `501 no_wallet`：
  ```jsonc
  { "binding": "WALLET", "service": "arcade", "entrypoint": "WalletService", "props": { "game": "kaipan" } }
  ```
  `props.game` 必须写 `kaipan`，参数里的 `game` 也写 `kaipan`；没写或对不上，所有调用都回 `bad_game`。平台带 `WalletService` 的版本已经部署，开盘才能部署带这个绑定的版本。
- **认人**：沿用开盘登录闸门的 `checkLogin`（`src/worker/gate.ts`，经 `ARCADE` 问 `/api/me`，只转发 Cookie 和 IP，3 秒超时，"没登录"和"平台不可用"分开），
  多带出 `user.id` 给钱包用。没登录回 401（`login`），平台不可用、`user` 没有 id 回 503（`unavailable`）。
  - **为什么不用 `arcade-kit/auth` 的 `whoIs`**（设计时写的是它，写代码时改了）：`whoIs` 只在 fetch 上挂了 `AbortSignal.timeout`，
    平台不理会中止信号、或者响应头回来了响应体迟迟不来时会一直挂住；`checkLogin` 对"等响应"和"读响应体"两段都按时放弃，开盘的闸门测试锁着这两种情况
    （`tests/worker-gate.test.ts`），换成 `whoIs` 这两条会挂。换的话还要加 `file:` 依赖、补 `Fetcher` 的类型、把共用包加进开盘部署流程的触发路径。
    等共用包补上这两段超时，再一起换过去。
- **三个动作**：参数都是一个对象，`game: 'kaipan'`、`mode: 'client'`。业务上的拒绝走返回值 `{ ok: false, error, wallet? }`，不抛异常。

| 动作 | 浏览器传 | Worker 做 | 钱包 |
|---|---|---|---|
| 带入 | `ref`、`tier` | `amount` = 这一档的一份（不能少带）；`until` = 现在 + 24 小时（按 Worker 的时钟）；`op` = `${ref}-in` | `buyin({ userId, game, ref, tier, amount, until, mode, op })` |
| 结回 | `ref`、`tier`、`bp`、`stats`（可选） | 检查 `bp` 是 0..`LIVE_MAX_BP`（0.11.0 起 70000）的整数（倍数的万分之几）；先 `view` 看钱包，`amount` = ⌊桌上这一份 × `bp` ÷ 10000⌋（0.11.2 起按带入时的金额，不信报的 `tier`；桌上没有这一份时按 `tier` 填，钱包只会回重发的原结果或 `no_stake`；看不了钱包回 503）；`op` = `${ref}-out`；`stats` 原样转发（0.6.5） | `settle({ userId, game, ref, amount, mode, op, stats? })` |
| 放弃 | `ref` | `op` = `${ref}-refund` | `refund({ userId, game, ref, mode, op })` |

- **ref 和 op 的格式**：钱包只收 8–64 位的 `[A-Za-z0-9_-]`。`ref` = `kaipan-` + `crypto.randomUUID()`（43 位），加上 `-in` / `-out` / `-refund` 最长 50 位。
  Worker 先按这个格式校验，不对直接回 400，不去碰钱包。
- **档位和一份**：Worker 里写一张和 `economy.md` 第 2 节一样的表（小 2,000、中 10,000、大 50,000、豪华 200,000），不读平台的代码。
  开局面板上的档位卡、钱包余额用浏览器的 `GET /api/wallet`（15.9，带档位表和桌上那一份），换设备的提示（2.4）也靠它看"开盘桌上有没有一份"。
- 结回由 Worker 按档位算金额，浏览器只给倍数（万分之几的整数，全程整数运算，不会因为小数误差少给 1 筹码），传多了 Worker 直接拒（不是防作弊，是防 bug 一下结出离谱的数）。钱包自己也只收到"带上桌的加 20 份"为止。
- **Worker 自己的回话**：路由、方法不对 404 / 405；没有 `X-Arcade: 1` 或 `Origin` 不是本站 403（`csrf`）；请求体不是 2 KB 以内的 JSON 对象 400（`bad_request`）；
  `ref`、`tier`、`bp`、`user` 不对 400（`bad_ref` / `bad_tier` / `bad_bp` / `bad_user`），这些都不问平台、不碰钱包；带了 `user` 而现在登录的不是他 409（`wrong_user`）。
  钱包回了（成功或业务拒绝）一律 200 原样转给浏览器，另加一个 `user`（现在登录的账号）；
  钱包绑定没有、RPC 抛异常、5 秒没回、回的形状不对是 503（`unavailable`）。
- **操作 id 按 ref 固定**：重试、刷新后重发都只算一次，钱包回第一次的结果并带 `dup: true`，游戏照常按结果显示。
- **钱包的回话怎么显示**（0.6.5 起照平台的错误码对照表 `docs/platform-backend.md` 15.10：每种都说清出了什么事、怎么办，不只回错误码；文字在 `src/view/liveText.ts`）：

| 回话 | 游戏里 |
|---|---|
| 带入 `ok` | 开局 |
| `no_funds`（余额不够这次带入；平台 0.10.2 起只要求够这一次） | 档位卡变灰，"钱包不够这一档"；真被拒时说"钱包里的筹码不够这一档。换小一档少带一点，或者去大厅领补给"，给「去领补给」（平台 `/wallet`）。开盘一档就是一份，"少带一点"就是换小一档 |
| `at_table`（同一个 `ref` 补码换了档；开盘每局新 ref、不补码，出现就是开盘写错了） | "这一桌带的是别的档，换一桌再开"，控制台记一笔 |
| `limit`（今天带入、领补给合计写满平台每天的写入上限，现在 1,000 次） | "今天开局太多了，明早 0 点恢复；桌上的照常结回。娱乐模式照常能玩" |
| 结回 `ok` | 结算页；进钱包的数用回话里的 `credited` |
| 结回 `ok`，`capped` > 0 | 结算页加一句"今天单机实盘赢够了：这局多出的 N 筹码没进钱包，明天再来"，N 就是 `capped` |
| `expired`（已经到期原样退回） | 这局改成娱乐局（2.4） |
| `no_stake`（这一份不在，多半已经结过） | 和 `expired` 一样处理：这局改成娱乐局，说"这一份已经结过了，看看钱包里的余额" |
| `busy`、`internal`、连不上、Worker 回 503 | 带入：不开局，`busy` 说"服务器今天有点忙，先不能带筹码开局，明早恢复"，`internal` 说"出了点问题，筹码没动，过一会儿再试"，连不上说"钱包暂时连不上"，都提一句娱乐模式照常玩；结回、放弃：记 `settling`，之后静默重试 |
| 结回、放弃遇到 `limit`（今天写满平台每天的写入上限，现在 1,000 次；按平台现在的规则结回、放弃不受这个限，留着兜底） | 和 `busy` 一样记 `settling`，之后重试（写入上限第二天就清了，不让这局作废） |
| `bad_*`、`bad_request`、`unknown_game` | 开盘自己的 bug：控制台记下，带入时说"出了点问题，这一份筹码没动，刷新一下再试"；结回时说"出了点问题，这一份筹码没动；一天后会原样退回钱包"，不自动重试，`kaipan.live` 留着排查 |

  `no_user` 按没登录处理。`internal` 是平台那边接住的任何异常（比如 D1 一时出错），大多是暂时的，和 `busy` 一样重试；操作 id 固定，重试也只算一次。
  被拒时回话里一般带当前的 `wallet`，余额直接拿来刷新显示。
- **每日上限**由钱包算（`economy.md` 第 4 节：净赢 = 当天这个游戏 client 模式结回的总额 − 带入的总额，份数按当天带入过的最高档）。开盘只负责把 `capped` 说清楚。
- **写入**：一局实盘正常是带入 1 次 + 结回 1 次（钱包各写 1 行）；开盘的 Worker 自己不存东西，仍然不用 D1、DO。

### 6.1 战绩小结（0.6.5，平台 0.10.0，`docs/platform-backend.md` 5.10）

结回时顺带报这一局的小结，平台记进钱包里的 `career`，给战绩页、排行榜、称号墙用。不带也照常结回。

- **谁算**：浏览器在一局结束、记成 `settling` 时算一次（`src/core/career.ts` 的 `liveSettleStats`），存进 `kaipan.live` 的 `stats`，重发时原样再带。
  开盘的 Worker 只原样转发（平台规定游戏 Worker 不改、不补），形状由平台校验：不合格整份忽略、钱照常结，回话带 `statsIgnored`。
- **报什么**：`rounds` 1；`wins` 资产涨了（`bp` > 10000）为 1；`best` = 结回 − 带入（亏了为 0）；`titles` = 结局称号 + 打法（`s_` 开头），提前收手不是结局、只报打法（0.6.8）；
  `max: { bp }`（最好的资产倍数，万分之几）；`sum: { limitup }`（涨停天数累计）。JSON 后在 256 字节以内（测试锁着）。
- **称号的名字**：`public/titles.json`（部署后是 `/games/kaipan/titles.json`），由 `titlesJson()` 生成，测试锁住两边一致；加称号时改 `career.ts`，再重新生成这个文件。
- 净赢、本周净赢由平台按钱算，开盘不报。

## 7. 和现有功能的关系

- **档案**：实盘局的规则和娱乐局不一样（只打几个月、账单轻），不算通关、不进各组合的最好成绩、不解锁人设和难度、不算成就；图鉴（见过的股票、群友、道具、事件、小知识）照记。
  「提前收手」的局没打完，和娱乐局里没打完的一样不记。档案里另记实盘的局数和总结回，留到个人页那一步（`economy.md` 第 5 步）再加，0.6.0 没做。
- **每日挑战、排行榜**：只在娱乐模式里，和实盘无关。
- **云存档**：一局进行中的进度本来不同步；`kaipan.live` 也只在本机（钱包那边有桌上那一份的记录，换设备时靠它提示）。
- **本机存储**：新 key `kaipan.live`，写进模块 `AGENTS.md` 的 key 表。
- **调试**：调试会话（`?debug=1`）里不能开实盘。
