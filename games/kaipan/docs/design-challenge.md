# 《开盘》异步挑战（社交第二期，0.13.0）

> 规范见仓库根 `docs/social.md` 第 2 节：结算页「发给好友挑战」，把这一局的种子和设置做成链接，好友打开就是同一个开局，两人的成绩挂在同一个挑战下互相看得到；
> 靠规则核心的确定性，不需要服务器重算；每个挑战一行，结果每人一行。本稿写开盘要交给平台存什么、怎么开局、成绩比什么；平台接口见 `docs/platform-backend.md` 15.18。
> 代码：`src/core/challenge.ts`（payload 生成和校验、分数）、`src/platform/challenge.ts`（调平台接口）、`src/view/challenge.ts`（画面状态）。

## 1. 「同一个开局」要带哪些东西

| 字段 | 内容 | 为什么 |
|---|---|---|
| `seed` | 这局的种子 | 规则核心的随机全从它分流出来 |
| `setup` | 这局的开局设置原样（`RunSetup`：`persona`、`difficulty`，短局还有 `short: { months, billMult, goal }`） | 人设和难度决定开局资产、账单和消息失真；短局的规则开局时已经抄进设置，跟着设置走，以后改 `BALANCE.short` 也不影响这个挑战 |
| `segment` | 这局用的行情段 id；模拟行情为 `null` | 段平时按种子哈希在段库里挑，段库加了新段，同一个种子就会挑到别的段。所以要写明是哪一段，开局时强制用它（和每日挑战用冻结段池同理） |
| `v` | 发起时的开盘版本号（`APP_VERSION`） | 账单、情报、事件这些数值不在设置里，跨版本可能变（每次改数值都会动）。版本对不上照样能打，但结果页标一句「版本不同，结果可能对不上」 |

- 整个 `payload` 是开盘自己的 JSON（约 200 字节），平台原样存、原样回，不解析。开盘读回来时自己校验：种子格式、`setup` 只许上面这几个键（`isRankedSetup` 的口径）、人设和难度合法、段 id 在段目录里。不合格就提示「这个挑战打不开」，不开局。
- **哪些局能发**：娱乐局（短局、完整一年）能发。
  - 每日挑战不用发：当天所有人本来就是同一局，已经有全站榜。
  - 实盘不能发，第一版不给按钮：实盘的成绩是结回倍数、连着钱包，好友那边开出来是不带筹码的局，规则也不一样（5 个月、按档放大）。比的东西对不上，容易让人以为是在赌筹码。
  - 调试设置开的局（带 `account`、`items` 等）也不能发。
- **种子会不会泄露行情**：链接里有种子和段 id，懂行的人能在本地把这一局先模拟一遍。开盘的取向是「排行榜不防作弊」，这里同样不防；正常玩的人看不到这些。

## 2. 流程

1. **发起**（结束页，娱乐局，有平台、已登录）：「分享」旁边多一个「挑战好友」。
   - 点了把 `payload` 和发起人这局的成绩（第 3 节）交给平台，拿回挑战 id。
   - 发起人这局要已经记进档案、交过分（不是被判无效的局），按钮才出来。
   - 链接是游戏地址加 `?challenge=<id>`，弹一个小框：「复制链接」，有系统分享时多一个「发给朋友」（点击里直接调，iOS 才认）。
2. **打开链接**：开盘启动时看到 `challenge` 参数，就向平台要这个挑战（`payload`、发起人昵称和成绩、已有结果）。
   - 先弹一张卡：「老王挑战你：职场新人阿韭 · 普通 · 短局 5 个月，他通关、剩 ¥13.2 万」，按钮是「接受挑战」和「先不了」。
   - 本机有没打完的局时，提示会顶掉它（和「新游戏」一样问一次）。
   - 平台的挑战接口都要登录（站点本来就要登录才能进游戏），所以不做「没登录也能打」。读完就把 `?challenge=` 从地址里去掉，刷新不会再弹。
   - 打不开（不存在、过期、payload 校验不过、不是开盘的挑战）一律说「这个挑战打不开了」；人满、平台在省额度、连不上各有一句。
3. **开局**：按 `seed`、`setup` 开局，行情强制用 `segment` 那一段（`segmentFor(seed, 段 id)`）。
   - 行情段下载失败时**不退回模拟行情**（那就不是同一局了），提示一句、不开局，可以再点链接重试。
   - 发起人当时是模拟行情的，这边也用模拟行情。
   - 接下的挑战记在 `kaipan.challenge`（挑战 id、种子、发起人、版本，只记最近一个）：中途关页面，回来点「继续」打完，按种子认出来照样交。
4. **打完**：结束页交成绩到这个挑战，交完写「挑战里第几名 · 共几人」，「看成绩」打开成绩表（前 50 名，我那一行标亮）。
   - 已经交过的人再打一遍，平台回「交过了」和原来那条，结束页写「之前交过，只算第一次」。
   - 交不上（连不上、平台在省额度）给「重试」，不自动重试；打不开了、人满了不给重试。
   - 交过成绩的人再打开同一个链接，直接看成绩表，不再弹挑战卡。
5. **档案**：照每日挑战的规矩记。
   - 人设、难度可以是还没解锁的，不算进解锁进度，也不占「最好成绩」。
   - 图鉴和成就照常点亮。
   - 档案按局记，不按挑战去重：同一个挑战再打一遍，图鉴、成就照常算，成绩只有第一次交给平台。

## 3. 成绩比什么

- **分数**沿用每日挑战的 `dailyScore`，同一套设置下是公平的：
  - 通关 = `1e11 + 最后账户（元）`；
  - 没通关 = 还上了几个月。
  - 也就是先比通没通关，通关的比剩多少钱，没通关的比撑了几个月。同一个挑战人设相同、开局资产相同，直接比钱数没问题（和分享卡用比例不一样，那是跨局比）。
- **每人只算第一次打完的那一局**：链接里有种子，再打一遍等于背过了行情，不公平。想再打可以，但结果页写「只算第一次」，不再交。
- **交给平台的**：
  - `score`（整数，平台拿它排序）；
  - `stats`（成绩表显示用，开盘自己的 JSON）：`{ title, growth }`，称号和资产涨跌（千分之几）。通关与否、钱数、月数都能从 `score` 读出来，不重复交。
  - 这些只是展示，平台不解析；读别人的按白名单校验，不合格的整份不用。
- **平台排序的规矩**：分数高的在前，同分先交的在前。

## 4. 平台接口（15.18）

开盘直接调（不经共用包），写请求带 `X-Arcade: 1`：

| 动作 | 开盘传 | 开盘要回 |
|---|---|---|
| 发起 `POST /api/challenges` | `game: 'kaipan'`、`payload`（第 1 节）、发起人的 `score` 和 `stats` | `id`、`until` |
| 打开 `GET /api/challenges/<id>` | — | `game`、`payload`、发起人、前 50 名（昵称、`score`、`stats`、是不是我）、人数、我的名次 |
| 交成绩 `POST /api/challenges/<id>/results` | `score`、`stats` | `ok`，或 `already` 和原来那条 |

- `payload` 和 `stats` 都是游戏自己的 JSON，平台只限大小（各 ≤ 1 KB）、原样存。
- 平台定的：30 天过期、每人每天发起 20 个、每个挑战最多 100 人。开盘按状态码说话：401 没登录、404 打不开了（不存在和过期一样）、409 人满了、429 今天发得太多、503 平台在省额度；400/403/413 是开盘自己交错了，当 bug。
- 单独部署（没有平台）不显示「挑战好友」，`?challenge=` 打开时直接进开始菜单。

## 5. 验收

- 单测：
  - `payload` 生成与校验（不合格的种子、多余的设置键、不认识的段都拒）；
  - 同一 `payload` 两次开局逐位相同；
  - 分数沿用 `dailyScore`；
  - 平台回话的校验和状态码对照（假 fetch）；
  - 挑战局的档案不动解锁进度、不占最好成绩，没解锁的难度也能记。
- 冒烟（假平台，`npm run shot -- --challenge`）：
  - 发起 → 拿到链接 → 另一个上下文打开链接 → 接受 → 打完 → 交成绩 → 结果页两人都在；
  - 行情段下载失败时不退回模拟行情。
