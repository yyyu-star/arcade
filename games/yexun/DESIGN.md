# 《夜巡》设计稿

> 模块 `games/yexun`（Worker 名 `yexun`，路径 `/games/yexun/`）。2026-10-16 起稿，所有者和主线当天商定玩法，主线当天两次修订（不做服务端录像校验；质量验收五条）。
> 本文是这个游戏的设计正本：玩法、数值骨架、架构、验收。数值的实际值以 `src/content/` 为准，配平结果以模拟器跑出来的表为准（第 8 节）。
> 跨模块的规范以仓库根 `AGENTS.md`、`docs/economy.md`、`docs/balance.md` 为准；冲突时以它们为准。

## 0. 一句话

**道士夜巡雪夜古镇**：只管走位，法器自动出手，升级三选一、法器进化，成群的跳尸纸人小妖扑上来；
两个模式平起平坐：**守夜**（撑到天亮）和**夜探**（进镇搜宝，按时撤出）。都能娱乐，都能带筹码。

名字：工作名《夜巡》，短、好记、点题。备选《雪夜镇邪》《守夜人》，由主线和所有者定，定了只改显示名（模块 id `yexun` 不改）。

题材只是化名的民间志怪：跳尸、纸人、灯笼鬼、狐火都是幻想造型；不涉及真实伤亡，不嘲弄真人，不出现真实宗教团体、人名、地名。

这是拉新的招牌游戏，质量不低于开盘。每条都要有可量的证据，写进对应 PR：

| # | 要求 | 怎么量 |

## 2. 两个模式

| | 守夜（经典幸存者） | 夜探（搜打撤） |
|---|---|---|
| 场地 | 古镇外的雪原，3,200 × 3,200 的有界场地，稀疏的枯树、石头、残碑（只装饰，不挡路） | 古镇大地图 6,400 × 6,400：街巷、院墙（挡路）、四座镇门；宝箱散在院子和街角 |
| 目标 | 撑到天亮（15:00）；14:00 起大怪"尸王"出场，打倒它天提前亮 | 搜宝箱捡宝物，在撤离点开着的时候走进去撤出 |
| 时间线 | 每分钟一档刷怪表，2:30 / 5:00 / 7:30 / 10:00 / 12:30 有事件（围圈、精英、群冲），14:00 大怪 | 撤离点：5:00–6:00 随机开一座镇门、10:00–11:00 再开一座、14:00–15:00 四门全开；15:00 天亮还在镇里算"迷失"（和死亡一样） |
| 节奏 | 越到后面怪越多越硬，法器成型后清屏 | 怪随时间变强，深处的宝箱更值钱、有守宝的巡夜将；越晚撤搜得越多、风险越大 |
| 娱乐 | 局外成长（铜钱买永久加成、解锁角色和法器）、成就、每日挑战排行 | 宝物进"藏宝阁"图鉴，可换铜钱；铜钱和成长两个模式通用 |
| 实盘 | 带入一份，按撑了多久结回：太早死输光、中段约保本、撑到天亮赢、打倒大怪赢最多 | 带入一份，撤出时按带出的宝物价值结回；死在里面（或迷失）这一份和背包都丢 |
| 波动 | 小，看技术 | 大，看技术也看胆子 |
| 胜（娱乐胜率口径） | 撑到天亮 | 活着撤出 |

共同点：一场 15 分钟上下（夜探早撤更短）；同一套主角、法器、被动、升级、进化；同一套操作。

### 2.1 一局怎么玩（两个模式共用）

- **只管走位**：键盘 WASD / 方向键，手机左半屏任意处按下出虚拟摇杆（松手消失）。方向量化成 32 向（第 5.4 节）。
- **法器自动出手**：每件法器有自己的冷却、目标规则（最近的、朝向、随机、绕身）。
- **吃魂火升级**：怪死掉落魂火（经验），靠近自动吸；升级时暂停弹出三选一卡片（新法器 / 法器升级 / 被动），最多 6 件法器 + 6 件被动。
- **进化**：法器满级（8 级）且持有对应被动时，下一个宝箱必出进化（第 3.3 节）。
- **宝箱**：守夜里精英掉落；夜探里散在地图上（也是宝物来源，第 2.3 节）。
- **掉落**：铜钱（局外货币）、肉包（回血）、符纸卷（吸全屏魂火），按掉落流随机。

### 2.2 守夜的时间线（骨架，数值在 `src/content/waves.ts`）

| 0:00–1:00 | 纸人（成群、很弱） | 0:05 第一波从正前方来，保证 10 秒内第一次升级 |
| 1:00–2:30 | 纸人 + 小鬼火（快、脆） | |
| 2:30 | | 纸人围圈（一圈 60 只从四面合拢） |
| 2:30–5:00 | 跳尸（一跳一跳，中等） | |
| 5:00 | | 第一只精英：石狮怪（大、慢、掉宝箱） |
| 5:00–7:30 | 跳尸 + 灯笼鬼（远处吐慢火球） | |
| 7:30 | | 小鬼火群冲（一条直线横穿） |
| 7:30–10:00 | 狐妖（冲刺）+ 跳尸 | |
| 10:00 | | 两只精英：跳尸将军 |
| 10:00–12:30 | 混编，数量到上限 | |
| 12:30 | | 纸人海（上限内最大的一波） |
| 14:00 | | 大怪"尸王"：三段技能（跳砸、召跳尸、吐尸气圈），血条在顶部 |

### 2.3 夜探

- **地图**：古镇按格子生成骨架（街、院、墙），每张图有固定的"镇子模板" + 种子决定宝箱、巡夜将、撤离门的位置。第一版 2 个模板，以后加。
- **宝箱三档**：木箱（街边，打开 1 件普通宝物）、铜箱（院里，2 件，有时带一只精英守着）、金箱（镇子中心和庙里，3 件，巡夜将守着）。
  宝箱打开要站在旁边 1.5 秒（读条，挨打不打断但会被推开）：搜就有风险。
- **宝物**：约 40 种，分四档（凡 / 良 / 珍 / 绝），每件有铜钱价值；捡到放进背包（第一版不限格）。藏宝阁记"见过哪些"，娱乐模式撤出后背包换铜钱。
- **怪**：和守夜同一套怪物表，按"夜探时间线"刷，并随时间加强；离镇子中心越近越凶。巡夜将是会追人的精英。
- **撤离**：撤离门开着时走进门圈站 3 秒撤出（挨打不打断）。地图边上的箭头指向开着的门，剩余时间在顶部。
- **别让人因为找不到门输光**（主线 2026-10-16）：14:00 起顶部换成醒目的"天亮倒计时"（最后 30 秒变红、心跳音），屏幕边上常驻箭头指向**最近的**开着的门并写距离，
  地面上从主角脚下画一串指向那扇门的脚印；每扇门开的时候全屏提示一次"东门开了"。机器人小白也只靠这些提示找门，配平时量"小白迷失的比例"（目标 ≤ 10%）。
- **死亡 / 迷失**：这一局背包里的宝物全丢；娱乐模式还能拿到这局捡的铜钱的一半（不让人输得太难受），实盘这一份结回 0。

### 3.6 局外成长（娱乐模式；实盘不生效）

铜钱只在游戏里，和筹码完全分开：**筹码不能买加成，铜钱不能换筹码**。

- 永久加成 8 项（力量、护体、体魄、神行、灵气、悟性、福缘、复活 1 次），每项 3–5 级，价格逐级涨；随时能全部退还重配。
- 解锁：角色、第 7–8 件法器（第 3 步）、夜探第二个镇子模板。
- 成就约 30 个（撑到天亮、打倒尸王、各进化各一次、藏宝阁集齐一档……），给铜钱和称号；称号文件 `public/titles.json` 给平台战绩页用（平台 5.10）。

## 4. 实盘

### 4.1 规则

- 两个模式都用**固定角色（小道士）和固定配置，永久加成不生效**（公平、好配平）。
- 档位 = 地图危险度：小 / 中 / 大 / 豪华（`docs/economy.md` 第 2 节档位表，一份 2,000 / 10,000 / 50,000 / 200,000）。危险度改怪的血、伤害、刷怪密度和精英频率，**不改规则**。
- 带入固定是这一档的一份（Worker 定，浏览器只报档位）；`mode: client`；结回走 Worker（第 6.5 节）。
- 默认一场最多赢 3 份、最多输 1 份（`docs/economy.md` 第 2 节）。夜探要不要放宽到 5 份，等模拟数出来报主线定。

### 4.2 结回倍数（`src/content/live.ts`，数值由模拟器定，这里是形状）

**守夜**：按撑到的时间 t 连续地涨（逐拍插值，不跳台阶），打倒尸王额外加：

| 撑到 | 倍数（初值） |
|---|---|
| ≤ 3:00 | 0 |
| 5:00 | 0.25 |
| 10:00 | 1.00 |
| 14:00 | 1.30 |
| 天亮 15:00 | 1.80 |
| 打倒尸王 | 3.00 |

曲线从 3:00 起平滑上升，不会出现"4 分 01 秒才有钱"的断崖（主线 2026-10-16）。选档卡上画这条小曲线（横轴时间、纵轴倍数，标出保本点、天亮、尸王），结算时在曲线上标出这一局停在哪。

**夜探**：倍数 = clamp(带出的宝物价值 ÷ 这一档的基准价值, 0, 封顶)；死亡或迷失为 0。基准价值按模拟定，让"5 分钟早撤"约 0.5、"10 分钟撤"约 1.3、"15 分钟撤"约 2 上下（越晚越多、越险）。

结回 = 带入 × 倍数（向下取整，按万分之一传 `bp`，同开盘）。

### 4.3 配平目标（`docs/balance.md` 第 2、3 节，模拟器量）

两个模式同档位每场期望对齐同一个目标，方差不同（守夜集中、夜探分散）：

| 档位 | 小白 | 普通 |
|---|---|---|
| 小 | +0.05 ～ +0.15，赢的场次 ≥ 50% | +0.20 ～ +0.40 |
| 中 | −0.05 ～ +0.05 | +0.10 ～ +0.20 |
| 大 | −0.20 ～ −0.10 | 0 ～ +0.10 |
| 豪华 | ≤ −0.20 | −0.05 ～ +0.05 |

娱乐难度 新手 / 普通 / 高手：小白胜率 ≥ 60% / 40–50% / ≤ 30%，普通 ≥ 75% / 55–65% / 40–50%（胜的口径见第 2 节表）。
设计文档同时写出"小档普通玩家每小时期望多少份"（一场按 15 分钟算）。

## 5. 架构

```
games/yexun/
├─ src/core/      模拟核心：固定节拍、确定性，不碰 DOM、网络、时间、随机
├─ src/content/   内容表：法器、被动、进化、怪物、刷怪表、角色、地图模板、实盘倍数
├─ src/view/      Phaser 4 画面层 + DOM 界面（菜单、卡片、HUD 文字）
├─ src/platform/  本地存储（yexun. 前缀）、云存档、平台接口（/api/me、钱包读、交分）
├─ worker/        Worker：登录闸门、独立模式根路径、实盘 buyin/settle/refund（自己一份 tsconfig）
├─ tools/         机器人模拟、冒烟截图、内存估算、字体子集化
└─ tests/         vitest
```

### 5.1 模拟核心 `src/core/`

- **固定节拍**：每秒 30 拍。`step(state, input)` 推进一拍并返回这一拍的事件（命中、击杀、升级、开宝箱、进化、撤离、结束）。
- **输入**：这一拍的方向（0 = 不动，1–32 = 32 向）+ 可选的升级选择（0–2）。升级弹卡时核心进入"选择中"，不推进时间，只等选择。
- **原地修改（主线批准的例外）**：几百个单位每秒 30 拍整体复制太慢，`step` 原地修改它拥有的状态（AGENTS.md 第 4 节"输出新状态"对本模块放宽）。
  存档和回放用"种子 + 输入"重算；确定性用重放测试锁住（状态指纹）。写进模块 `AGENTS.md`。
- **数据布局**：怪、子弹、掉落物用定长的并列数组（`Float64Array` / `Int32Array`，结构数组），空位用空闲表复用，热路径不分配对象。
- **碰撞**：均匀格子分区（格子 64 单位），每拍重建一次（计数排序，O(n)）。怪与怪之间做轻推挤（只和同格、邻格的比），子弹查邻格的怪。
- **上限**：怪 300、子弹 400、掉落物 400（超了就合并最远的魂火）。按模拟和手机实测再定。
- **确定性**（主线 2026-10-16 修订：不强求定点数）：
  - 坐标、速度用 JS 的双精度浮点；`+ - * /` 在所有引擎上按 IEEE 754 逐位一致；
  - **禁止** `Math.random`、`Date`、`performance`，以及 `Math.sin/cos/tan/atan2/sqrt/hypot/exp/log/pow/cbrt` 这类引擎可以近似实现的函数；
    方向用 32 向（和需要时 256 向）的单位向量表，表是**写死在源码里的常数**；需要开方的地方（追踪、归一化）用固定迭代次数的牛顿法（`src/core/fmath.ts`），只用四则运算；
  - 允许 `Math.floor/ceil/trunc/round/abs/min/max/sign/imul`（结果是精确的）；
  - 遍历顺序固定（数组下标），不用 `Map`/`Set` 的迭代顺序决定结果，不用 `Array.prototype.sort` 排有相等元素的东西（用稳定且带下标的比较）；
  - 随机数：自己写的 `sfc32`（只用 `Math.imul` 和位运算），按用途分流：刷怪、掉落、升级选项、宝箱、怪的行为、地图生成，各一条流，种子由总种子和用途名哈希得到。
    一条流多用一次不影响别的流（比如多掉一个铜钱不会改变下一张升级卡）。
  - 架构测试扫 `src/core/` 和 `src/content/` 的源码，出现上面禁止的东西就失败。
- **单位**：时间以拍计；距离以"单位"计（主角宽约 40 单位）；伤害、血量是整数，减伤、暴击等百分比按整数万分比算后向下取整。

### 5.2 内容表 `src/content/`

纯数据 + 小函数（伤害公式、刷怪表查询），被核心读取。改数值只改这里；数值变化要过模拟器（第 8 节）。

### 5.3 画面 `src/view/`

- **Phaser 4**（WebGL，失败回 Canvas）。世界层由 Phaser 画：地面、阴影、怪、子弹、特效、伤害数字；界面层用 DOM（菜单、升级卡、结算、设置），字小也清楚、好做无障碍和 44 像素检查。
- **插值**：画面按真实时间跑 60 帧（或屏幕刷新率），核心按 30 拍；画面在两拍之间插值位置。
- **本地预测（验收 ②"一帧内响应"）**：摇杆一动，主角的**画面位置**当帧就按新方向挪（从上一拍的位置外推），下一拍核心算出的位置到了再平滑并上；只影响主角的画面，不进核心。
- **对象池**：怪、子弹、魂火、伤害数字、粒子都用池；同屏精灵 ≤ 1,200。
- **镜头**：跟人，带一点前瞻（朝移动方向偏一点），有界场地在边上停住。
- **打击感**（验收 ②）：命中闪白（两帧着色）、受击后退、死亡碎片、发光叠加（ADD 混合）、拖尾、暴击和大招停顿（hit-stop：画面暂停送拍 40–80 ms，核心按拍走，不影响确定性）、轻微震屏、伤害数字弹跳、连斩毛笔字横幅加墨点。
- **HUD**：左上回大厅、头像、血条护盾；顶部中间计时（夜探加撤离倒计时）、经验条和等级；右上击杀、铜钱；右侧技能格（法器图标 + 冷却遮罩）；夜探多一个背包价值和指向撤离门的箭头。
- **iOS / 手机**（AGENTS.md 第 4 节，照开盘的做法）：触屏设备渲染倍数封顶 2，地面这类整屏大图按 1 倍；高度按 `visualViewport` 算的 CSS 变量；双指放大时不改尺寸；WebGL 丢失等几秒才提示、恢复时收起；safe-area 四边让出；省内存设备（触屏且 `deviceMemory ≤ 4` 或 iOS）关粒子、伤害数字减半。
- **横屏**：游戏按横屏设计；手机竖屏时提示"横过来玩"（画面照常可用，但界面按横屏排）。

### 5.4 输入和录像（本地）

- 方向量化成 32 向：键盘 8 向是其中的子集；摇杆按角度取最近的一向，拉动不足死区算不动（只要方向，不要力度：力度会让录像变大、手感也不更好）。
- **录像 = 规则版本 + 模式 / 档位 / 难度 / 角色 / 加成快照 + 种子 + 每一拍的方向（游程压缩）+ 升级选择（按拍号）**。一局 15 分钟 27,000 拍，摇杆平均几拍换一次方向，压缩后几 KB 到十几 KB。
- **只存在本机**（主线 2026-10-16 修订）：`yexun.replays` 存最近 5 局和每个榜自己最好的一局，总量控制在 300 KB 内（超了先删最旧的普通局）。页面能回放自己的录像（暂停、2×、4×）。
  这是玩法功能（看自己怎么打的、发给朋友看的截图），也方便复现 bug。
- 规则版本变了的旧录像标"旧版本，可能放不对"，不删。
- **为什么不做服务端录像存储和校验**：所有者 2026-10-16 定"太重就不做"，排行榜和其他游戏一样不防作弊（`docs/project.md` 第 3 节第 7 条）。
  **以后要加**：录像格式已经是"种子 + 输入"，加一个上传接口、在 Worker 或维护者工具里用同一份核心重放比分数即可，核心不用改。

### 5.5 平台接入 `src/platform/`

- 存储 key 一律 `yexun.` 前缀：`yexun.save`（铜钱、加成、解锁、藏宝阁、成就、统计）、`yexun.settings`（音乐、音效、震屏、伤害数字）、`yexun.replays`、`yexun.live`（进行中那一份的 ref 和账号，用于断线后结回或放弃）、`yexun.cloud`（云存档元数据）。
- 云存档（平台 5.5）：同步 `profile` 一个槽（铜钱、加成、解锁、藏宝阁、成就、统计，估计 < 4 KB）和教程标记；不同步打到一半的那一局、设置、录像。合并：集合并集、计数取大、铜钱取"按局 id 去重后的流水"之和（避免两台设备各花各的出现负数，具体写进 `cloud.ts` 的注释）。
- 进页面先 `GET /api/me`（`detectPlatform`）：独立部署时藏起登录、云存档、排行榜、实盘，"回大厅"改成回游戏首页。

### 5.6 Worker `worker/`

- 入口只导出 `default`（单独部署时具名导出会让 Worker 起不来）。
- 首页三种写法过 kit 的 `loginGate`；站点根 `/` 和 `/api/me` 过 `standaloneRoot`（独立模式）。
- `/games/yexun/api/live/{buyin,settle,refund}`：照开盘 0.11.2——浏览器只给 `ref`、`tier`、`bp`（倍数万分比）、可选战绩小结；带入金额固定是这一档一份、到期 24 小时由 Worker 定；
  **结回前先 `WALLET.view` 取桌上这一份的金额按它算**，不信浏览器报的档位；CSRF（`X-Arcade: 1` + Origin）、请求体 ≤ 2 KB、超时 5 秒；独立部署回 501 `no_wallet`。
- **没有 Durable Object**（不做联机、不做服务端录像），所以 `wrangler.jsonc` 只有静态资源。

### 5.7 排行榜（第 6 步）

照其他游戏的简单版：页面直接 `POST /api/scores`，不经过游戏 Worker，不防作弊（平台 15.5）。

| 榜 | boardId | 分数 |
|---|---|---|
| 守夜 | `vigil`（固定榜，要平台登记） | 撑到的秒数 × 10,000 + 击杀数（击杀 < 10,000）；打倒尸王另加 1 亿，显示"天亮 · 击杀 n" |
| 夜探 | `raid`（固定榜，要平台登记） | 单局撤出的宝物价值（铜钱） |
| 每日挑战 | `daily-YYYY-MM-DD` | 全服同一种子同一张图，单日守夜、双日夜探（北京日期）；固定角色、不带加成；编码同上，`public/daily.json` 写怎么显示 |

只交娱乐模式和每日挑战的成绩（实盘的成绩不上榜，免得档位不同混在一起）；守夜、夜探榜只收"普通"及以上难度。一局结束出结算画面时交一次。

## 6. 性能预算

| 项 | 预算 | 怎么量 |
|---|---|---|
| 核心一拍 | 300 怪 + 400 子弹时 ≤ 2 ms（中端手机），≤ 0.5 ms（电脑） | `tools/bench.ts` 在 Node 跑满载一局；手机上 HUD 调试层显示 |
| 一帧 | 16.7 ms；中端手机横屏满载 p95 ≤ 20 ms（≥ 50 帧） | 冒烟里记 `requestAnimationFrame` 间隔；手机实测写进 PR |

| 图集 | 运行时用 Canvas 程序画进一张 ≤ 2048 × 2048 的图集（省内存设备 1024 或按 1 倍） | 开局一次，计时写进 PR |
| 内存 | 省内存设备 ≤ 200 MB | `tools/mem-probe.ts` 估算 |
| 模拟器 | 一局（无画面）≤ 1 秒；2,000 局一格用多线程跑完 | `tools/sim.ts` |

## 7. 画风和声音

### 7.1 画风（参考《通神榜》的风格，不照搬它的角色、图、界面布局）

- **浅色雪地 + 稀疏点缀**：月光下偏冷的浅灰白雪地、零星的青石板、枯树、石头、残碑；底色浅，特效和怪才能跳出来。
- **角色**：大头 Q 版、粗黑描边、平涂加一层阴影；动作靠压扁拉伸和晃动（走路上下颠、受击压扁、死亡弹起）。
- **怪**：一种一个主色，精英带鬼火紫光（ADD 叠加的外发光），都有脚下椭圆阴影。
- **特效**：金色（符、剑）、青蓝（雷、鬼火）、朱红（火、朱砂）三套主色；发光叠加、拖尾、碎片、墨点。
- **界面**：宣纸底色 + 墨色描边的卡片，朱红印章做强调；数字用粗体无衬线，标题和连斩横幅用毛笔字。

### 7.2 素材

- 全部程序生成：开局用 Canvas 2D 画进图集（角色、怪、法器、特效、地面贴片），矢量路径写在 `src/view/art/`。
- 毛笔字：开源可商用书法字体（候选 Ma Shan Zheng，SIL OFL 1.1），核实许可后按游戏里用到的字子集化（`tools/subset-font`），来源和许可证全文写进 `ASSETS.md`。
- 不引入任何别人的图片、音频。

### 7.3 音乐

WebAudio 程序合成：五声音阶的笛子 / 古筝音色（简单的加法合成 + 包络），夜里低沉的鼓点；守夜按时间段加层，尸王出场换曲；夜探更安静、撤离门开时加紧张的打击层。

### 7.4 音效表（每项一种合成配方，验收 ③）

法器 8 种各一（剑风、符纸爆、铜钱叮、飞剑嗖、镜光嗡、雷击、铃声、喷火）、命中、暴击、怪死、魂火拾取（音高随连吸上升）、升级、三选一选中、进化（长）、宝箱开（守夜）、宝箱读条和开（夜探）、宝物入袋（按档位）、受伤、低血心跳、精英出现、尸王出现、尸王技能 3 种、撤离门开、撤离成功、天亮、死亡。
同一帧同一种音效最多播 2 个，避免几百个命中音叠成噪音。

## 8. 机器人和配平工具 `tools/`

- **两个玩家模型**（`docs/balance.md` 第 1 节，带种子、确定性、不读隐藏信息——这个游戏没有隐藏信息，但机器人只用屏幕上看得到的范围）：
  - **小白**：每 10 拍重新决定方向，朝"离怪最远 + 有魂火"的方向走但带噪声，偶尔贴脸；升级随便挑（偏好新法器）；夜探见箱就开，撤离门开了才往那边走、常常走不到。
  - **普通**：每 3 拍决定，按怪的密度场躲（势场法），会绕圈收魂火；升级按进化配方挑；夜探会算"走到撤离门要多久"决定开不开下一个箱，按背包价值和血量选第一扇还是第二扇门。
- `tools/sim.ts`：多线程跑 N 局，输出第 4.3 节那张表（均值 ± 2 倍标准误、胜率、时长分布、倍数分布）和每档"每小时期望"。
- `tools/shot.ts`：无头浏览器冒烟（端口 0 或 5178/4178），走主流程、两种尺寸截图、44 像素检查、控制台零报错、`--lowmem`、双指放大、WebGL 丢失恢复。
- `tools/bench.ts`：核心满载每拍耗时。

## 9. 测试 `tests/`

- **重放一致性**：同种子同输入跑两遍，状态指纹（所有数组的哈希）逐拍相同；中途"从种子 + 输入重算"得到的指纹和直接跑的一样；录像编解码往返一致。
- **跨实现一致**：一份写死的"种子 + 输入"及其终局指纹作为金标准，Node 里跑 vitest、无头浏览器冒烟里再跑一次，都要对得上。
- **架构**：`src/core/`、`src/content/` 不出现禁止的函数和对象（第 5.1 节），不 import 画面、平台代码；`worker/` 不 import 核心（只取实盘档位表）。
- **内容**：刷怪表每分钟都有、进化配方对得上法器和被动、伤害公式边界、实盘倍数单调。
- **实盘**：Worker 路由（CSRF、请求体、单独部署 501、超时、按钱包里那一份的金额结回），照开盘的测试。
