# 《夜巡》设计稿

> 模块 `games/yexun`（Worker 名 `yexun`，路径 `/games/yexun/`）。本文是这个游戏的设计正本：现在是什么、为什么这样设计、怎么验收、怎么配平。
> 数值的实际值以 `src/content/` 为准，配平结果以模拟器跑出来的表为准（第 8 节）；逐版变化看 [CHANGELOG.md](CHANGELOG.md)，本文不记过程。
> 跨模块的规范以仓库根 `AGENTS.md`、`docs/economy.md`、`docs/balance.md` 为准；冲突时以它们为准。界面流程和布局规则见 [docs/art-v3.md](docs/art-v3.md)，配色见 [docs/palette.md](docs/palette.md)。

## 0. 一句话

**道士夜巡雪夜古镇**：只管走位，法器自动出手，升级三选一、法器进化，成群的跳尸纸人小妖扑上来；
两个模式平起平坐：**守夜**（撑到天亮）和**夜探**（进镇搜宝，按时撤出）。都能娱乐，都能带筹码（实盘）。

题材只是化名的民间志怪：跳尸、纸人、灯笼鬼、狐火都是幻想造型；不涉及真实伤亡，不嘲弄真人，不出现真实宗教团体、人名、地名。

## 2. 两个模式

| | 守夜（经典幸存者） | 夜探（搜打撤） |
|---|---|---|
| 场地 | 古镇外的雪原，3,200 × 3,200 的有界场地，稀疏的枯树、石头、残碑（只装饰，不挡路） | 古镇大地图 6,400 × 6,400：街巷、院墙（挡路）、四座镇门；宝箱散在院子和街角 |
| 目标 | 撑到天亮（15:00）；14:00 起大怪"尸王"出场，打倒它天提前亮 | 搜宝箱捡宝物，在撤离点开着的时候走进去撤出 |
| 时间线 | 每分钟一档刷怪表，定点事件（围圈、精英、群冲）见 2.2，14:00 大怪 | 撤离门分三个时段开（2.3）；15:00 天亮还在镇里算"迷失"（和死亡一样） |
| 节奏 | 越到后面怪越多越硬，法器成型后清屏 | 怪随时间变强，深处的宝箱更值钱、有守宝的巡夜将；越晚撤搜得越多、风险越大 |
| 娱乐 | 局外成长（铜钱买永久加成、解锁角色和地图）、成就、每日挑战排行 | 宝物进"藏宝阁"图鉴，可换铜钱；铜钱和成长两个模式通用 |
| 实盘 | 带入一份，按撑了多久结回：太早死输光、中段约保本、撑到天亮赢、打倒大怪赢最多 | 带入一份，撤出时按带出的宝物价值结回；死在里面（或迷失）这一份和背包都丢 |
| 波动 | 小，看技术 | 大，看技术也看胆子 |
| 胜（娱乐胜率口径） | 撑到天亮 | 活着撤出 |

共同点：一场 15 分钟上下（夜探早撤更短）；同一套主角、法器、被动、升级、进化；同一套操作。

### 2.1 一局怎么玩（两个模式共用）

- **只管走位**：键盘 WASD / 方向键，手机左半屏任意处按下出虚拟摇杆（松手消失）。方向量化成 32 向（第 5.4 节）。
- **法器自动出手**：每件法器有自己的冷却、目标规则（最近的、朝向、随机、绕身）。
- **吃魂火升级**：怪死掉落魂火（经验），靠近自动吸；升级时暂停弹出三选一卡片（新法器 / 法器升级 / 被动），最多 6 件法器 + 6 件被动（合成一次多一格）。
- **进化**：法器满级（8 级）且持有对应被动时，下一个宝箱必出进化（第 3.3 节）。
- **宝箱**：守夜里精英掉落；夜探里散在地图上（也是宝物来源，第 2.3 节）。
- **掉落**：铜钱（局外货币）、肉包（回血）、符纸卷（吸全屏魂火）、符咒炸弹、铜钱袋，按掉落流随机；场上还有可碰碎的摆设（灯笼架、纸扎）。数值在 `src/content/player.ts`。

### 2.2 守夜的时间线（雪原；数值在 `src/content/waves.ts`）

强度曲线不是直线：每个大事件后给 20–30 秒"收获期"（刷怪减半、掉落多：精英倒下后 25 秒、爆点刷出来后 30 秒），节奏验收见 13.3。会远程的怪（灯笼鬼、雪魅）每种不超过刷怪比例的 8%。
危险 3 起另有常规怪**提灯鬼**（不怕火，给火流派一个对手）：5 分钟起占常规怪 15%，12 分钟起 25%。

### 2.3 夜探

- **地图**：按格子生成骨架（街、院、墙），三个模板（古镇、渡口、山寺）+ 种子决定宝箱、巡夜将、撤离门的位置。第一次进夜探是**教学镇**：小地图、第 3 分钟开第一座门、死了不丢包。危险 0 也在第 3 分钟开第一座门。
- **宝箱三档**：木箱（街边，打开 1 件普通宝物）、铜箱（院里，2 件，有时带一只精英守着）、金箱（镇子中心和庙里，3 件，巡夜将守着）。
  宝箱打开要站在旁边 1.5 秒（读条，挨打不打断但会被推开）：搜就有风险。
- **宝物**：45 种，分四档（凡 15 / 良 14 / 珍 10 / 绝 6），每件有铜钱价值；捡到放进背包（不限格）。藏宝阁记"见过哪些"，娱乐模式撤出后背包换铜钱。
- **怪**：和守夜同一套怪物表，按夜探自己的刷怪表（`RAID_MINUTES`）刷，并随时间加强；离镇子中心越近越凶（`RAID_ZONE`）。每个镇有一种特色怪（古镇更夫鬼、渡口溺鬼、山寺石僧）。
  巡夜将是会追人的精英，另有两只夜里游荡的；最值钱的院子由守门 Boss 镇门石兽守着。
- **撤离**：撤离门开着时走进门圈站 3 秒撤出（挨打不打断）。四座镇门：5:00–6:00 随机开一座、10:00–11:00 再开一座、14:00–15:00 四门全开；15:00 天亮还在镇里算"迷失"（和死亡一样）。
- **别让人因为找不到门输光**：14:00 起顶部换成醒目的"天亮倒计时"（最后 30 秒变红、心跳音），屏幕边上常驻箭头指向**最近的**开着的门并写距离，
  地面上从主角脚下画一串指向那扇门的脚印；每扇门开的时候全屏提示一次"东门开了"。机器人小白也只靠这些提示找门，配平时量"小白迷失的比例"（目标 ≤ 10%）。
- **死亡 / 迷失**：这一局背包里的宝物全丢；娱乐模式还能拿到这局捡的铜钱的一半（不让人输得太难受），实盘这一份结回 0。
- **后半段**（为的是 6 分钟以后不只剩躲怪等门；参数在 `RAID_LIVE`/`RAID_LATE`，规则在 `src/explore/raid.ts`；教学镇没有）：
  - 补货：6:00 起每 90 秒，挑 3 个开过的箱子（离主角 500 以外，不挑宝库）重新封上、换一批东西，一波比一波深（深度 +0.25 / 波）；
  - 宝妖：5:00、10:00 各一只，从离主角 900–1,600 的路口出来，见人就跑（比主角慢一点，被墙角堵住跑不掉），不打人；45 秒后钻地跑掉；打倒直接进背包两件好宝物（按金箱、深度 1 抽）；
  - 鬼市：7:00–8:00 镇中心最近的路口摆三个摊，各摆一件（中间那摊按金箱抽，绝品机会大），站在摊前 1 秒、身上铜钱够就按价值 × 0.7 买下。
    这是把局里捡的铜钱换成能带出去的宝物，所以会抬高撤出价值、也就抬高实盘倍数（配平时机器人普通玩家要会逛鬼市）；
  - 宝库和钥匙：最深的金箱开局就贴着封条，8:00 以后、身上有钥匙才能搜，开出 6 件；钥匙是 5:00 以后打倒的第一只精英或守卫掉的（宝妖不算），一局一把。
    这里的时刻是开局后已过的时间；局里的提示一律按 HUD 的"离天亮"倒计时写（写"8:00 以后"玩家会按倒计时理解，早到了打不开），走近宝库时箱子上方显示还差多久开封、开封后有钥匙显示"可以搜了"。
  - 都按夜探自己的随机流（`raid-late`）抽，同种子同输入逐位相同，录像和每日挑战能复现。**不加"越晚撤越多倍"的倍数**：越晚撤多出来的价值全来自上面这些，配平只调基准价值（4.2）。

### 2.4 新手保护和受伤补偿（规则核心里，确定性；实盘档照用，对谁都一样）

都是明写的规则，不藏；数值在 `src/content/waves.ts`（DANGERS、OPEN_TICKS、EARLY_TICKS、FIRST_RUN_GUARD）和 `src/content/player.ts`（MERCY）。

| 规则 | 触发 | 幅度 | 为什么 |
|---|---|---|---|
| 开场慢怪 | 危险 0 前 30 秒 | 怪走路 ×0.5 | 原地不动也撑得过第一次升级 |
| 大吸珠 | 危险 0 全程（危险 1 ×1.4） | 吸珠范围 ×2.4 | 剑砍死的怪掉的珠子站着也吸得到 |
| 先给法器 | 危险 0 前 4 次升级 | 三张里至少两张是法器 | 先有能打的 |
| 第一局不死 | 这台设备上的第一局，3 分钟前 | 血最少留 1 | 第一局至少玩到第一个精英 |
| 开局减伤 | 危险 0–2 前 5 分钟 | 挨打 ×0.8 | 开局手忙脚乱少掉点血 |
| 受伤补偿 | 血低于上限的 40% | 肉包掉率 ×3；补出来的肉包最多每 20 秒一个 | 挨打多的人帮得多，会躲的几乎用不上 |

受伤补偿有上限，故意卖血不占便宜：机器人"站着挨打"（不躲、只等肉包）的胜率和撑的时间都远低于正常躲怪（`tests/pace.test.ts` 锁住）。

另外两条新手保护：
- 第一局锁危险 0（菜单只给危险 0，`dangerOpen`）；
- 连着倒下 3 局（认输、赢了都清零）问一次"要不要降低伤害"：开着时挨打 ×0.7（`ASSIST`），成绩不进总榜，设置里随时能开关。

**危险档**（`DANGERS`，危险 2 是配平基准；表里是代码里的绝对值，血和伤害相对基础怪）：

| 档 | 血 / 伤害 / 数量 | 其他 |
|---|---|---|
| 0 | ×0.72 / ×0.6 / ×0.85 | 开场慢怪、大吸珠、先给法器；难的常规怪晚一分钟出；精英晚 30 秒 |
| 1 | ×1.0 / ×1.0 / ×1.0 | 怪种按时出；精英晚 30 秒 |
| 2 | ×1.2 / ×1.2 / ×1.1 | 精英按时间线 |
| 3 | ×1.3 / ×1.3 / ×1.12 | 没有开局减伤；精英比时间线早 20 秒；出提灯鬼 |
| 4 | ×1.45 / ×1.45 / ×1.14 | 每次精英多一只 |
| 5 | ×1.46 / ×1.46 / ×1.2 | 每次精英多一只；两只尸王各 75% 血（两只都倒了才算打倒） |

撑到天亮解锁下一档；实盘四档固定用危险 0 / 2 / 3 / 4。夜探另有更缓的一条坡（`RAID_DANGERS`，4.2）。难度台阶的目标是危险 2→3 普通机器人胜率降 8–10 个点（见 8.1）。

**咒印**（`src/content/meta.ts`；撑到过一次天亮才开，最多挂 3 条，每条这局的铜钱多 25%，实盘不开）：疾（怪快 15%）、枯（肉包和回血减半）、定（不能刷新）、众（怪多 25%）、凶（每次精英多一只）、暗（看得更近，只改画面）。

#### 3.3b 双修

双修 = 两件不同流派（类型或五行）的法器合成，把两边的打法接在一起，只给一点额外输出、不翻倍（数值 `DUAL_FX`）。门槛比普通合成低：**一件进化、另一件满级**就行（要两件都进化时机器人每 20 局只合成 1–2 次，玩家更难见到）。

| 两件 | 双修 | 变化 |
|---|---|---|
| 飞剑 + 符咒 | 符剑合璧 | 飞剑打中的怪被贴一张符，一秒多后炸开 |
| 金钟罩 + 火葫芦 | 焚天金钟 | 护盾在身，外圈一圈火持续烧；盾碎时地上留下一圈火 |
| 桃花雨 + 镇魂铃 | 铃落桃花 | 铃声一响，空中的花瓣追着怪落下，落点也更大 |
| 纸兵 + 火葫芦 | 火兵 | 纸兵贴身时每秒在脚下点一小摊火，倒下时留一摊大的 |
| 纸兵 + 镇魂铃 | 鸣兵 | 纸兵倒下时铃声震开一圈怪 |

双修的强度用对照臂量（`tools/sim.ts --nodual`：同种子、条件满足也不合，拿正常臂里合成了的局和对照臂同一局比胜率和天亮倍数，就是净强度；不拿"合成那一刻还活着、没合成"的局比，那样量到的多半是构筑成没成型）。目标见 8.1。

### 3.6 地图

守夜六张，场地都是 3,200 × 3,200 的有界场地；挡路的东西是轴对齐矩形（只算脚底那块地），主角和怪都推不进去，子弹和掉落物不管（掉进去的宝箱、肉包挪到边上）。
空气墙在画面上看得见（栅栏、竹篱、石堤、院墙，墙外盖夜雾；docs/art-v3.md）。

- **雪原**：开阔，稀疏的枯树、石头、残碑（只装饰，不挡路）。一开始就开。
- **义庄**：出生点四周一圈院墙（边长 1,040），四面墙中间各留一个门洞；院里北边是正堂，两排棺材；院外散着棺材和残墙；跳尸 ×1.5、枯骨 ×1.3 的刷怪比例。一开始就开，卡上标"难"。
- **竹林**：约 90 丛竹子（轴对齐块，有血，血随面积），十字宽路加一条斜路；桃木剑、火舌、飞出去和转着的法器、雷、金钟罩碎裂、炸弹碰到就扣血，同一丛 8 拍内只算一次，倒了就从 `w.blocks` 拿掉、不再长回来。
- **河滩**：一条横河、一条竖河，桥是水区之间的缺口；水里主角和怪 ×0.55（蝙蝠、水鬼和各图自己的特色怪不受水和冰影响），河岸有石头、芦苇。
- **冰湖**：中间 2,080 见方的冰面，冰上主角速度逐拍靠向输入、松手按摩擦滑停（约 100–150 单位），怪同样滑、被打退滑得更远；冰上散着石头。
- **荒庙**：正中一座破庙，院墙塌了好几处，北边大殿；院里一尊香炉，庙外三尊。**香火区**（`MapDef.incense`）：每尊香炉四周 260×240 的一块，站在里面每秒多回 1.6 血，但香火引怪（怪的上限 ×1.3，刷怪速度 ×1.7），回血和被围之间要自己拿捏。
  庙祝鬼射程 250、占刷怪 4–6%：占 10–14%、射程 320 时远程怪站着不动越积越多，普通机器人危险 2 胜率 0%，这是下限提醒。**实盘暂不开放**（`LIVE_MAP_CLOSED`），系数配好再开（8.1）。

解锁（`MAP_UNLOCK`，按"守夜最长撑过多久"现算、不存档）：竹林 4 分钟，冰湖、河滩 8 分钟，荒庙 10 分钟。河滩按难度该排 12 分钟，但改大会把已经开了河滩的老玩家锁回去，所以和冰湖一样 8 分钟。
地图卡的顺序按小白胜率排：雪原 → 竹林 → 冰湖 → 河滩 → 义庄 → 荒庙。规则在 `step.ts` 的 `chop`、`slidePlayer`、移动里的水和冰；地形和障碍的画法在 `view/art/terrain.ts`：电脑上平铺雪地 + 一张地形叠层，省内存设备把雪地、底色调和地形合成一张 0.34 倍的不透明图，整屏只画一遍。

### 3.8 局外成长（娱乐；实盘不生效）

- 铜钱不存总数，存**流水**（每局赚的、每次花的各一条，带 id）：两台设备各玩各花，云存档合并时按 id 取并集再加总，不白送也不扣成负数（`save.ts` 的 `mergeSave`）。
  每局铜钱 = 局里捡的 ×（1 + 0.25 × 咒印条数）；另有按来源列在结算页的奖励（撑的分钟、击杀、天亮、打倒尸王，后四项每高一档危险 +20%；每日首胜；见 `RUN_BONUS`），成就的奖励另记一条。
- 解锁：角色、咒印、危险档（通关上一档）、地图、夜探模板。
- 图鉴：怪物图鉴（见过 / 打倒过多少）、法器图鉴（用过 / 满级 / 进化 / 合成）、藏宝阁（夜探宝物 45 件，四档）；主界面显示总收集度。

### 3.9 选卡三件套（所有者 10-20，0.4.4；`src/content/picks.ts`）

- 起步刷新 3、封禁 2（加成「刷新」每级 +1，只娱乐）；进化一件法器、打倒精英或首领各补 1 次刷新，最多攒 9 次。
- 跳过不再换 15% 经验，改抽一样随机小奖（单独一路种子 RNG，录像能复现）：铜钱 10 + 2×等级（35%）、回 20% 血（25%，满血时在其他三样里重抽）、
  下一次升级多一张卡（25%，不叠加）、刷新 +1（15%）。
- 选卡三个按钮各配一行小字；顶栏铜钱底下写「夜市可花，剩下局后存入」。实盘局暂照旧（2 / 1、跳过换魂、不补刷新），配平 PR 一起打开。

## 4. 实盘

### 4.1 规则

- 两个模式的配置固定，**永久加成（perks）、咒印、降低伤害不生效**（公平、好配平）。实盘可以**选已解锁的角色**；守夜还可以**选已解锁的地图**（夜探的"地图"是镇子，本来就能选）。
  **不带加成、咒印的理由**：它们是拿铜钱买的永久成长，带进实盘就等于老玩家固定多赚，新老玩家同一份筹码的期望不同；角色和地图是并列的选择，不是成长，所以放开。
  不传角色、地图就是小道士、雪原。荒庙和纸兵流暂不进实盘（`LIVE_MAP_CLOSED`、卡池），系数配好再开（8.1）。
- 档位 = 危险度的固定配置：小 / 中 / 大 / 豪华（`docs/economy.md` 第 2 节档位表，一份 2,000 / 10,000 / 50,000 / 200,000）守夜分别**固定映射娱乐的危险 0 / 2 / 3 / 4**，只维护一套怪表。
  刷新、封禁次数固定（2 / 1）；选卡三件套（3.9）实盘暂不开，配平 PR 重配系数时一起打开。
  局内铜钱和娱乐一样，打完存入账户（所有者 10-20：账户铜钱只买永久加成和请角色，永久加成不进实盘，不影响赔率公平）。夜探开小、中、大三档（对应夜探危险 0 / 1 / 2，见 4.2），豪华档等模拟器出表再开。
- 带入固定是这一档的一份（Worker 定，浏览器只报档位）；`mode: client`；结回走 Worker（第 5.6 节）。夜巡自己的档位名是 small / medium / large / luxe，带入时换成钱包的 small / mid / big / lux（`LIVE_TIERS.wallet`）。
- 默认一场最多赢 3 份、最多输 1 份（`docs/economy.md` 第 2 节）。平台还有每个游戏每天净赢 10 份的上限兜底。

### 4.2 结回倍数（`src/content/live.ts`、`src/content/explore.ts`，数值由模拟器定，这里是形状）

**守夜**：按撑到的时间连续地涨（逐拍插值，不跳台阶），打倒尸王额外加。曲线是 `VIGIL_SHAPE`（3:00 以前为 0，5:00 占天亮倍数的 5.6%，10:00 22%，14:00 28.8%，15:00 100%），
四档形状相同、只按各档的天亮倍数 `dawnBp` 缩放，打倒尸王再加 0.2（`VIGIL_BOSS_ADD_BP`，不缩放），一场封顶 3 份：

| 撑到 | 小（危险 0） | 中 / 大 / 豪华（危险 2 / 3 / 4） |
|---|---|---|
| ≤ 3:00 | 0 | 0 |
| 5:00 | 0.07 | 0.09 |
| 10:00 | 0.28 | 0.35 |
| 14:00 | 0.37 | 0.46 |
| 天亮 15:00 | 1.27 | 1.60 |
| 打倒尸王 | 1.47 | 1.80 |

为什么是这个形状：中途回得少、天亮给得多，小白（早死）和普通（多半撑到天亮）的期望才拉得开，四档才能同时落进 balance.md 4.4 的区间；曲线从 3:00 起平滑上升，没有"4 分 01 秒才有钱"的断崖。
天亮倍数随档位不降（小 ≤ 中 ≤ 大 ≤ 豪华，`tests/live-client.test.ts` 锁住），不然玩家看到的是"大档更难、给得更少"。选档卡上画这条小曲线（横轴时间、纵轴倍数，标出保本点、天亮、尸王），结算时标出这一局停在哪。

目标（balance.md 4.4，实盘期望，份）：小 普通 +0.45～0.60 / 小白 +0.15～0.30，中 +0.30～0.45 / 0～0.15，大 +0.20～0.30 / −0.10～0，豪华 +0.05～0.15 / −0.25～−0.10。
定"夜巡是普通玩家每天拿筹码最有效的途径"后，小档目标最高。每次改内容或危险档都要重拟 `dawnBp`；上一轮全量（0.3.2，新倍数 1.27/1.60/1.60/1.60）里五个流派的实盘期望极差：危险 2 0.17、危险 3 0.19、危险 4 0.22，各档期望值以重跑 sim 为准。
已知的取舍：危险 3 只比危险 2 难一点，按"天亮倍数随档位不降"大档小白会比目标上限高一点，接受。

**夜探**：撤出时倍数 = clamp((带出的宝物价值 + 早搜奖励) ÷ 基准价值, 保底, 封顶 3)；死亡、迷失、认输、中途关页面为 0。基准按"档位 × 镇子"各一个（`RAID_LIVE.base`），不按一个数，免得"挑镇子赚钱"。
档位 → 夜探危险：小 0、中 1、大 2。夜探的危险档单独一条更缓的坡（`waves.ts` 的 `RAID_DANGERS`）：危险 1、2 取守夜危险 0→1 的三分之一、三分之二处，危险 3 起顺延守夜的 1、2、3。
理由：夜探没有天亮可撑、还有巡夜将，同一档比守夜难得多（普通玩家用守夜的危险 1 只撤出 45%、危险 2 约 30%），中、大档怎么定基准都够不着目标区间。

**认真搜要比开门就走多拿至少 0.15 份**（否则认真玩的人会觉得白搜了）。三处设计：
- **保底按撤出时刻给**（`liveFloor`）：从 1 份线性涨到这一档的满额。小档 5 分钟给满 1.6；中档第一座门 5 分钟才开，开门就走也在 6 分钟左右，所以拖到 10 分钟给满 1.6；大档 8 分钟给满 1.25。
- **早搜奖励**（`RAID_EARLY`）：前 5 分钟开离出生点 1,200 以内的木箱、铜箱，宝物结算时价值 ×1.3（不改抽到什么，只在结算加价；死了包丢了奖励也没了）。纯刷保底不碰箱子拿不到。
- **后半段提价**：补货每波深度 +0.25、宝库 6 件（2.3）。只奖励待到 6、8 分钟以后的人。

拟合口径：全量模拟，每格 2,000 局：三镇 × 三档 × 小白 / 普通 / 贪心。普通玩家 10 分钟后才走，贪心 13 分钟后，小白第一座门开就走。"开门就走"= 手熟、几乎不死的人只拿保底，按 95% 撤出 × 小白撤出时间中位（小档 4 分钟、中大档 6 分钟）时的保底 − 1 估。
拟合时的结果（实盘期望，份；基准后来按新种子微调过，以 `explore.ts` 为准）：普通 小 +0.56～0.58 / 中 +0.44～0.45 / 大 +0.29；小白 小 +0.14～0.19 / 中 −0.05～+0.07 / 大 −0.07～−0.10；开门就走 小 +0.40～0.42 / 中 +0.29 / 大 +0.12～0.13；普通比开门就走多 0.16。
取舍：要拉开 0.15，普通玩家只能放在区间上沿；出界的两格是山寺小白（小、中档），山寺本来就难。贪心比普通再多 0.06～0.12：多待多搜有回报。

结回 = 带入 × 倍数（向下取整，按万分之一传 `bp`，同开盘）。

### 4.2a 角色、地图系数

选哪个角色、哪张地图，同一档的实盘期望（份）不应差出 0.15 份以上，否则玩家会"挑角色、挑地图赚钱"。差出去的单独给一个**实盘倍数系数**（万分比，没写 = 10_000 = 不调），小道士、雪原是基准，永远不写；角色、地图本身的数值和对局规则不动：

- **守夜**：`LIVE_CHAR_BP`、`LIVE_MAP_BP`（`src/content/live.ts`），按档写，乘在这一档的 `dawnBp` 上，所以天亮、尸王前的曲线一起按同一比例缩放，尸王加成不缩放；结果始终封顶 3 份。按档写是因为难度随档位涨得快的角色、地图（义庄、冰湖）在各档需要的补偿不一样。
- **夜探**：`RAID_LIVE.charBp`，按档写，可以按镇子细分；乘在按保底、封顶算好的倍数上（`liveMultiplier`），结果至少 1 份、最多封顶。接在结回上而不是基准价值上：胖师叔、采药女的撤出率高，撤出就有保底，调基准价值压不下去。
  实盘局的角色由核心带上，`settleRaid` 自己取，界面不用管。
- **口径**：角色和地图先**分开扫**（角色在雪原、地图用小道士），两个系数默认相乘；乘出来偏离同档平均 ±0.15 份以上的**组合**单独写在 `LIVE_COMBO_BP`（角色 × 地图 × 档），写了就用整套系数**替换**乘积，尸王加成照旧不缩放。
  原因：胖师叔、采药女这类角色在义庄、冰湖上并不是"各强各的"，乘出来的系数会把他们抬高很多。夜探只有角色一个维度，不需要组合表。目标是每档同档各角色（地图、镇子）之间的普通玩家期望极差 ≤ 0.15 份；系数取到 100（1%）。
  不用封顶、不改加法：组合偏高的原因是角色和地图的强弱不独立，封顶管不到，直接替换乘积最简单。
- **义庄豪华档天亮就封顶 3 份**：义庄豪华档系数 23_700，天亮倍数 1.6 × 2.37 ≥ 封顶，**赢一局（不论打没打倒尸王）直接拿满 3 份**；输了仍按撑到的时间折算（同样放大 2.37 倍）。普通玩家这档胜率约 30%，期望仍对齐小道士。
  要让天亮不封顶得把义庄豪华档的危险降一档，那是改玩法，不做；选模式屏的文字写清。
- **已知问题**：组合没有全扫（5 角色 × 4 地图 × 3 档 = 60 格，实测约 35 格），没测到的格仍按乘积，可能偏离；小白只作参考没有拟合（同一个系数对小白不通用，小白在义庄的实盘期望比普通玩家低得多）；
  采药女、胖师叔在夜探里仍是最强的（系数压平了期望，没压平"撤出率"），界面上不要写"夜探最强角色"。
- 荒庙、纸兵和新角色组合按同一套方法拟合，偏离同档平均 ±0.15 份以内才开放（8.1）。

### 4.3 配平目标（`docs/balance.md` 第 2、3 节，模拟器量）

两个模式同档位每场期望对齐同一个目标，方差不同（守夜集中、夜探分散）：

| 档位 | 小白 | 普通 |
|---|---|---|
| 小 | +0.05 ～ +0.15，赢的场次 ≥ 50% | +0.20 ～ +0.40 |
| 中 | −0.05 ～ +0.05 | +0.10 ～ +0.20 |
| 大 | −0.20 ～ −0.10 | 0 ～ +0.10 |
| 豪华 | ≤ −0.20 | −0.05 ～ +0.05 |

（夜巡实盘现行的目标在 balance.md 4.4，数值抄在 4.2。）
娱乐是危险 0–5 六档；balance.md 第 3 节的"新手 / 普通 / 高手"按危险 0 / 2 / 4 量：小白胜率 ≥ 60% / 40–50% / ≤ 30%，普通 ≥ 75% / 55–65% / 40–50%（胜的口径见第 2 节表）。

## 5. 架构

```
games/yexun/
├─ src/core/      模拟核心：固定节拍、确定性，不碰 DOM、网络、时间、随机
├─ src/content/   内容表：法器、被动、进化、怪物、刷怪表、角色、地图、夜探模板、实盘倍数
├─ src/explore/   夜探的规则（地图生成、宝箱、守卫、撤离、结算）
├─ src/view/      Phaser 4 画面层 + DOM 界面（菜单、卡片、HUD 文字）+ 程序画的图和合成的声音
├─ src/platform/  本地存储（yexun. 前缀）、云存档、实盘浏览器端
├─ src/online/    排行榜分数、每日挑战、分享卡、社交部件
├─ src/replay/    本机录像
├─ worker/        Worker：登录闸门、独立模式根路径、实盘 buyin/settle/refund（自己一份 tsconfig）
├─ tools/         机器人模拟、冒烟截图、手感和耗时测量、封面、字体子集化
└─ tests/         vitest
```

### 5.1 模拟核心 `src/core/`

- **固定节拍**：每秒 30 拍。`step(state, input)` 推进一拍并返回这一拍的事件（命中、击杀、升级、开宝箱、进化、撤离、结束）。
- **输入**：这一拍的方向（0 = 不动，1–32 = 32 向）+ 可选的升级选择（0–2）。升级弹卡时核心进入"选择中"，不推进时间，只等选择。
- **原地修改（主线批准的例外）**：几百个单位每秒 30 拍整体复制太慢，`step` 原地修改它拥有的状态（AGENTS.md 第 4 节"输出新状态"对本模块放宽）。
  存档和回放用"种子 + 输入"重算；确定性用重放测试锁住（状态指纹）。写进模块 `AGENTS.md`。
- **数据布局**：怪、子弹、掉落物用定长的并列数组（`Float64Array` / `Int32Array`，结构数组），空位用空闲表复用，热路径不分配对象。
- **碰撞**：均匀格子分区（格子 64 单位），每拍重建一次（计数排序，O(n)）。怪与怪之间做轻推挤（只和同格、邻格的比），子弹查邻格的怪。
- **上限**：怪 300、子弹 400、掉落物 400（超了就合并最远的魂火）。
- **确定性**（不强求定点数）：
  - 坐标、速度用 JS 的双精度浮点；`+ - * /` 在所有引擎上按 IEEE 754 逐位一致；
  - **禁止** `Math.random`、`Date`、`performance`，以及 `Math.sin/cos/tan/atan2/sqrt/hypot/exp/log/pow/cbrt` 这类引擎可以近似实现的函数；
    方向用 32 向（和需要时 256 向）的单位向量表，表是**写死在源码里的常数**；需要开方的地方（追踪、归一化）用固定迭代次数的牛顿法（`src/core/fmath.ts`），只用四则运算；
  - 允许 `Math.floor/ceil/trunc/round/abs/min/max/sign/imul`（结果是精确的）；
  - 遍历顺序固定（数组下标），不用 `Map`/`Set` 的迭代顺序决定结果，不用 `Array.prototype.sort` 排有相等元素的东西（用稳定且带下标的比较）；
  - 随机数：自己写的 `sfc32`（只用 `Math.imul` 和位运算），按用途分流：刷怪、掉落、升级选项、宝箱、怪的行为、地图生成，各一条流，种子由总种子和用途名哈希得到。
    一条流多用一次不影响别的流（比如多掉一个铜钱不会改变下一张升级卡）。
  - 架构测试扫 `src/core/` 和 `src/content/` 的源码，出现上面禁止的东西就失败。
- **单位**：时间以拍计；距离以"单位"计（主角宽约 40 单位）；伤害、血量是整数，减伤、暴击等百分比按整数万分比算后向下取整。

### 5.2 内容表 `src/content/`

纯数据 + 小函数（伤害公式、刷怪表查询），被核心读取。改数值只改这里；数值变化要过模拟器（第 8 节）。

### 5.3 画面 `src/view/`

- **Phaser 4**（WebGL，失败回 Canvas）。世界层由 Phaser 画：地面、阴影、怪、子弹、特效、伤害数字；界面层用 DOM（菜单、升级卡、结算、设置），字小也清楚、好做无障碍和 44 像素检查。
- **插值**：画面按真实时间跑 60 帧（或屏幕刷新率），核心按 30 拍；画面在两拍之间插值位置。
- **本地预测（验收 ②"一帧内响应"）**：摇杆一动，主角的**画面位置**当帧就按新方向挪（从上一拍的位置外推），下一拍核心算出的位置到了再平滑并上；只影响主角的画面，不进核心。
- **对象池**：怪、子弹、魂火、伤害数字、粒子都用池；同屏精灵 ≤ 1,200。
- **镜头**：跟人，带一点前瞻（朝移动方向偏一点），有界场地在边上停住。
- **打击感**（验收 ②）：命中闪白（两帧着色）、受击后退、死亡碎片、发光叠加（ADD 混合）、拖尾、暴击和大招停顿（hit-stop：画面暂停送拍 40–80 ms，核心按拍走，不影响确定性）、轻微震屏、伤害数字弹跳、连斩毛笔字横幅加墨点。
- **HUD**：布局规则见 docs/art-v3.md 第 2 节。
- **iOS / 手机**（仓库根 AGENTS.md 第 4 节，照开盘的做法）：触屏设备渲染倍数封顶 2，地面这类整屏大图按 1 倍；高度按 `visualViewport` 算的 CSS 变量；双指放大时不改尺寸；WebGL 丢失等几秒才提示、恢复时收起；safe-area 四边让出；省内存设备（触屏且 `deviceMemory ≤ 4` 或 iOS）关粒子、伤害数字减半。
- **图集**：开局用 Canvas 2D 画进四张图集，每张 ≤ 2048 × 2048：主图集、夜探图集、特色怪图集（含纸兵）、角色图集。主图集在渲染倍数 3 时已接近上限，新图放别的图集。
- **横屏与竖屏**：游戏按横屏设计；竖屏也能玩：世界缩放按屏宽定（一屏宽看 460 单位），竖屏开的局刷怪圈转 90°（`setup.tall`，录进录像），横屏局不受影响。

### 5.4 输入和录像（本地）

- 方向量化成 32 向：键盘 8 向是其中的子集；摇杆按角度取最近的一向，拉动不足死区算不动（只要方向，不要力度：力度会让录像变大、手感也不更好）。
- **录像 = 规则版本 + 模式 / 档位 / 难度 / 角色 / 加成快照 + 种子 + 每一拍的方向（游程压缩）+ 升级选择（按拍号）**。一局 15 分钟 27,000 拍，摇杆平均几拍换一次方向，压缩后几 KB 到十几 KB。
- **只存在本机**：`yexun.replays` 存最近 5 局和每个榜自己最好的一局，总量控制在 300 KB 内（超了先删最旧的普通局）。页面能回放自己的录像（暂停、2×、4×）。
  这是玩法功能（看自己怎么打的、发给朋友看的截图），也方便复现 bug。
- 规则版本变了的旧录像标"旧版本，可能放不对"，不删。
- **为什么不做服务端录像存储和校验**：排行榜和其他游戏一样不防作弊（`docs/project.md` 第 3 节第 7 条）。
  **以后要加**：录像格式已经是"种子 + 输入"，加一个上传接口、在 Worker 或维护者工具里用同一份核心重放比分数即可，核心不用改。

### 5.5 平台接入 `src/platform/`

- 存储 key 一律 `yexun.` 前缀，全表见 AGENTS.md 第 6 节。
- 云存档（平台 5.5）：同步 `profile` 一个槽（铜钱流水、加成、解锁、藏宝阁、成就、统计，估计 < 4 KB）和教程标记；不同步打到一半的那一局、设置、录像。合并：集合并集、计数取大、铜钱取"按局 id 去重后的流水"之和（避免两台设备各花各的出现负数，具体写进 `cloud.ts` 的注释）。
- 进页面先 `GET /api/me`（`detectPlatform`）：独立部署时藏起登录、云存档、排行榜、实盘，"回大厅"改成回游戏首页。

### 5.6 Worker `worker/`

- 入口只导出 `default`（单独部署时具名导出会让 Worker 起不来）。
- 首页三种写法过 kit 的 `loginGate`；站点根 `/` 和 `/api/me` 过 `standaloneRoot`（独立模式）。
- `/games/yexun/api/live/{buyin,settle,refund}`：照开盘 0.11.2——浏览器只给 `ref`、`tier`、`bp`（倍数万分比）、可选战绩小结；带入金额固定是这一档一份、到期 24 小时由 Worker 定；
  **结回前先 `WALLET.view` 取桌上这一份的金额按它算**，不信浏览器报的档位；CSRF（`X-Arcade: 1` + Origin）、请求体 ≤ 2 KB、超时 5 秒；独立部署回 501 `no_wallet`。
- **没有 Durable Object**（不做联机、不做服务端录像），所以 `wrangler.jsonc` 只有静态资源。

### 5.7 排行榜

照其他游戏的简单版：页面直接 `POST /api/scores`，不经过游戏 Worker，不防作弊（平台 15.5）。分数公式在 `src/online/score.ts`，榜的显示写在 `public/boards.json`、`public/daily.json`。

| 榜 | boardId | 分数 |
|---|---|---|
| 守夜总榜 | `vigil`（固定榜） | 危险档 × 1e10 + 撑到的秒数 × 1e4 + 击杀（击杀 < 1e4）；打倒尸王算撑满 900 秒再加 100 |
| 夜探总榜 | `raid`（固定榜） | 单局撤出的宝物价值（铜钱） |
| 无尽 | `endless`（固定榜） | 活了多少秒 × 1e4 + 击杀 |
| 每日守夜 | `daily-YYYY-MM-DD-vigil` | 撑到天亮：1e6 + 击杀；没撑到：撑了多少秒 |
| 每日夜探 | `daily-YYYY-MM-DD-raid` | 单局撤出的宝物价值 |

每日挑战：全服同一种子、同一张图、同一组当日咒印；固定角色、不带加成；规则版本变了榜名后面加 `-v<n>`。
只交娱乐和每日挑战的成绩（实盘不上榜）；每日挑战只进当天的每日榜，不进总榜；开了"降低伤害"的局不交总榜；认输的不交（无尽除外）。好友榜用平台的 `scope=friends`。一局结束出结算画面时交一次。

## 6. 性能预算

| 项 | 预算 | 怎么量 |
|---|---|---|
| 核心一拍 | 300 怪 + 400 子弹时 ≤ 2 ms（中端手机），≤ 0.5 ms（电脑） | `npm run bench -- --worst` 在 Node 跑满载；手机上带 `?fps` 看帧率 |
| 一帧 | 16.7 ms；中端手机横屏满载 p95 ≤ 20 ms（≥ 50 帧） | 冒烟里记 `requestAnimationFrame` 间隔；手机实测写进 PR |
| 首包 | 游戏代码 ≤ 250 KB gzip（Phaser 另算，单独成块缓存）；字体子集 ≤ 120 KB | 构建输出 |
| 图集 | 四张图集每张 ≤ 2048 × 2048（省内存设备渲染倍数 ≤ 2） | 开局一次，计时写进 PR |
| 内存 | 省内存设备 ≤ 200 MB | 暂无专用估算工具，靠渲染倍数封顶 2、图集尺寸和 `?lowmem` 冒烟兜底 |
| 模拟器 | 一局（无画面）≤ 1 秒；2,000 局一格用多线程跑完，大批量拆到 GitHub runner | `tools/sim.ts` |

实测（0.0.17，2026-10-17，Node）：`bench --worst`（300 怪满额、12 件法器全进化、主角无敌绕圈）每拍平均 0.24 ms、p99 0.53 ms、最慢 0.64 ms，p99 略超电脑 0.5 ms 的预算，可接受、不为它再改。
本机没有 GPU，无头浏览器的帧率是软件渲染的下限，一帧的预算以真机为准：带 `?fps` 打开，左下角显示每秒帧数、这一秒最长的一帧和场上怪数，手机横屏不到 30 帧不过关。

## 8. 机器人和配平工具 `tools/`

- **两个玩家模型**（`docs/balance.md` 第 1 节，带种子、确定性；这个游戏没有隐藏信息，但机器人只用屏幕上看得到的范围）：
  - **小白**（novice）：每 10 拍重新决定方向，朝"离怪最远 + 有魂火"的方向走但带噪声，偶尔贴脸；升级只挑看起来最强的（不全随机，随机选卡会拿到引魂灯这类不直接加战力的被动）；夜探见箱就开，撤离门开了才往那边走、常常走不到。
  - **普通**（normal）：每 3 拍决定，按怪的密度场躲（势场法），会绕圈收魂火；升级按流派单子和进化配方挑，会去凑双修的另一半；夜探会算"走到撤离门要多久"决定开不开下一个箱，逛鬼市、按背包价值和血量选第一扇还是第二扇门。夜探另有贪心（greedy）玩家，多待多搜。
  - 流派单子在 `tools/bots.ts` 的 BUILDS，和玩法说明用的 `guide.ts` 是同一份。
- `tools/sim.ts`：多线程跑 N 局，输出胜率、时长分布、倍数分布和每档实盘期望；`--json` 存每局结局（赢没赢、打没打倒尸王、撑了几拍、死因、第一次双修的拍）供离线拟合，`--from` 错开种子分片，`tools/sim-merge.ts` 拼表；`--nodual` 是双修对照臂。大批量（每格 ≥ 1,000 局）拆到 GitHub runner 上跑。
- `tools/shot.ts` / `tools/smoke.ts`：无头浏览器截图与冒烟（用法见 AGENTS.md 第 5 节）。
- `tools/bench.ts`：核心耗时；`tools/feel.ts`：手感；`tools/cover.ts`：大厅封面。

**配平方法**：先给弱流派补强，给强流派加克制它的怪，少砍法器；改数值的 PR 里贴同口径的结果表；节奏验收（13.3）写成机器人测试（`tests/pace.test.ts`）。

### 8.1 全流派配平口径

目标（所有者 10-20 定）：至少 10 种搭配能通关最高难度，各流派有轻微强弱但不明显。

- **搭配** = 一个主流派 + 一条进化或双修路线。同一流派走不同进化，算不同的搭配。只计机器人能稳定走出来的构筑。
  - **稳定走出** = 路线走成率 ≥ 30%（危险 5）。走成率是这条路线的进化或合成在局里做成的比例。不到 30% 的路线，要么给机器人加路线策略帮它凑，要么不计入 10 个。
  - 机器人照路线优先拿配方里的法器和被动，其余照流派表（模拟器用 `--build 流派:路线` 指定的做法是目标口径，要用时在 `tools/bots.ts` 里实现）。
- **流派**：剑修、符箓、镇守、五雷、烈火、纸兵，共 6 个。
- **通关最高难度** = 危险 5 撑到天亮。用普通机器人，每个搭配 ≥ 1,000 局，在 GitHub runner 上分片跑。通关率 ≥ 25% 算可实现；至少 10 个搭配达标，覆盖全部 6 个流派。
- **难度曲线**：危险 5 各流派最好搭配目标 30–45%（避免太容易）；仍要保证至少 10 个搭配走成率 ≥ 30%、通关率 ≥ 25%。危险 2→3 普通胜率降 8–10 个点。普通机器人在危险 5 上普遍接近 0 时，先报主线：给机器人加一档"高手"（更早躲尸王技能、更会绕圈），或调危险 5 本身；不擅自降最高难度。
  改危险档要同步核对实盘用到的档位系数（危险 0 / 2 / 3 / 4）。
- **流派平衡**：参考档 = 危险 2、普通机器人，每流派取它最好的搭配，各 ≥ 1,000 局。最高和最低通关率差 ≤ 12 个百分点；任一流派离平均 ≤ 7 个百分点。排名可以有先后，但不能出现某流派明显碾压或明显没法玩。
- **双修**：没有一条组合比同流派最好的单修高 8 个百分点以上（用 `--nodual` 对照臂量净强度）；频率上，普通机器人危险 4 每 20 局合成至少 5 次。
- **实盘**：荒庙、纸兵以及全部角色 × 地图组合，用 `LIVE_CHAR_BP`、`LIVE_MAP_BP`、`LIVE_COMBO_BP` 同一套方法拟合；偏离同档平均 ±0.15 份以内才开放。新内容和配平改动一起上实盘，系数验完前实盘不开放新地图和纸兵。
- **现状基线**（0.4.2，雪原，普通机器人，每格 1,000 局）：流派的危险 2 / 5 通关率见 3.4 的表，危险 2 各流派最好搭配之间差 6.4 个点；上一轮（0.4.0）基线里危险 5 只比危险 2 低约 10 点、范围 42–72%，太容易，需要拉陡危险 3–5。

### 13.3 一局节奏（守夜，机器人"普通"在危险 2 量，写成测试 `tests/pace.test.ts`，每项 ≥ 200 局的均值）

- 第一次升级 10–20 秒，前 30 秒最多 2 级（"打死一个怪就升级了"太快）
- 前 3 分钟升级 6–9 次，第 5 分钟前 10–14 次
- 全局升级 25–36 次（按会凑双修的机器人量），后半段每分钟 1.5–2.5 次（成型感在 8–10 分钟出现）
- 道具：精英宝箱 1 / 3 / 5 件（6% / 24% / 70%，纸扎老爷至少 3 件），开箱有演出；场上可碰碎的灯笼架、纸扎（开局散 36 个，主角 760 以内少于 4 个时每 12 秒补一个），碰碎掉肉包 30%、铜钱堆 32%、磁符 10%、符咒炸弹 8%、铜钱袋 12%；
  小怪另有千分之 1.2 掉符咒炸弹（半径 520 内小怪全倒，精英和 Boss 掉 8% 血）、千分之 1.5 掉铜钱袋（12–25 枚）；数值在 `src/content/player.ts`
- 每局都看得到铜钱进账，结算页按来源列：捡到的、摆设、铜钱袋、宝箱、撑的分钟（每分钟 10）、击杀（每 40 只 1）、天亮 120、尸王 200（这四项每高一档危险 +20%）、咒印加成、成就、每日首胜 150（`RUN_BONUS`）
- 精英 5 次（3:00、5:00、7:30、10:00、12:00），每次必掉宝箱；中期 Boss 8:00；尸王 14:00
- 每个大事件后 20–30 秒收获期（刷怪量、掉落量曲线能看出低谷）
- 3 分钟、8 分钟、12 分钟附近各有一个"小爆点"（围圈、群冲、纸人海）
- 夜探：危险 0 和教学镇第 3 分钟开第一座门；小白迷失 ≤ 10%

### 13.4 构筑

- 三选一 + 刷新（每局 2 次，局外可加）+ 封禁（每局 1–2 次）+ 跳过（换少量魂）
- 卡片和暂停页写清"进化还差哪个被动"
- 套装（标签 2 件、3 件）撑起 ≥ 5 个流派（3.4）
- 幸运属性（黄历）
- 配平：每个流派的机器人（普通）在危险 2 都能撑到天亮，没有"只有一种 build 能赢"—— sim 表（8.1）

### 13.5 留存

- 怪物图鉴、法器图鉴、藏宝阁，主界面显示总收集度
- 每日挑战两个（守夜、夜探），固定种子 + 当日咒印
- 守夜通关后开"无尽"（天不亮、怪一直涨、计时），实盘不开
- 排行：每日榜、总榜（守夜、夜探、无尽）、好友榜
- 本地录像回放（自己的）；分享卡（kit 的 share）；游戏内玩法说明

## 14. 和平台的关系（夜巡是平台体系里的一个游戏，不是孤岛）

| 平台能力 | 夜巡怎么用 |
|---|---|
| 账号、登录闸门 | Worker 首页过 kit 的 `loginGate`（5.6）；单独部署时游客 |
| 钱包、实盘 | 两个模式的实盘走平台钱包（client 模式，Worker 转 RPC，先 view 再结回）；配平按 `docs/balance.md`，档位按 `docs/economy.md` |
| 战绩 | 结回时带战绩小结 `stats`（平台 5.10），只转发不改 |
| 排行、每日挑战 | `POST /api/scores`：守夜、夜探、无尽总榜，每日挑战两个，好友榜 `scope=friends`（5.7） |
| 分享卡 | 结算页"分享这一夜"：kit 的 `arcade-kit/share`（`shareCard`），图上写时长、击杀、build、咒印；不上传 |
| 社交部件 | kit 的 `arcade-kit/social`：`mountSocial` 报位置（在菜单 / 守夜中 / 夜探中）、收好友邀请的横条；只在有平台且登录时挂 |
| 云存档 | `profile` 槽同步局外成长，教程标记一个槽；合并规则见 5.5 |
| 称号 | 成就给的称号写进 `public/titles.json`，形状照平台读它的格式（平台 5.10），平台战绩页、称号墙能显示 |
| 大厅 | 回大厅入口常驻左上，对局中离开先确认 |

不碰真钱：筹码只在实盘里带入结回；铜钱是游戏内货币，和筹码完全分开，不能互换。
