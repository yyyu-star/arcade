# 弹里个弹（games/danli）

回合制抛物线对战：萌宠和厨房道具大乱斗。两队小动物站在悬空的面团地形上，轮流调角度、按住蓄力、看风开炮，把对手打空血量或轰出画本就赢。
设计正本见 [DESIGN.md](DESIGN.md)，模块约定见 [AGENTS.md](AGENTS.md)，更新见 [CHANGELOG.md](CHANGELOG.md)，素材来源见 [ASSETS.md](ASSETS.md)。

现在是 0.4.0：单机，先进准备房间挑对阵（1v1、2v2、3v3，空位由电脑补，电脑可以是队友也可以是对手）、地图（11 张，或"随机"）和武器（8 把），
6 位电脑人物（橘子、团团、企企、柴柴、兔兔、鼠鼠）各拿自己喜欢的武器；常用道具（连发、三岔、加力）和特殊道具（纸飞机、锅盖）；WebAudio 现场合成的音效；
我方真人出局以后能快进或跳到结果；结算页有每个人的伤害、命中、轰出画本。地图、地形、远景、角色、武器图标和页面照美术代理的交付稿（见 ASSETS.md）。
0.3.0 加了好友房（下面"好友房"一节），0.4.0 加了 5 张新图（生日蛋糕城、火锅沸腾谷、披萨火山、寿司长台、下午茶花园）。没有特技、怒气和新手教程。

## 好友房

- 首页"好友房"：**开房间**，或者**输房间码**（6 位数字）；朋友发来的链接（`…/games/danli/?room=<码>`）打开就进房。
- 房间页：顶上房间码、"复制链接"（本站登录了还有"叫好友"，kit 的邀请面板）；进房的人自动坐进空位，点别的空位能换；
  每人在自己的位子上选小动物、武器，点"准备"；房主改对阵、地图，加电脑、替电脑换人物和武器、撤电脑，请一直不准备的人下场；
  真人都准备了、两队都有人，房主点"开打！"。没坐下的人（kit 一个房间最多 6 个人坐下）在旁边看，对局中进来的先看，打完再坐。
- 对局：轮到你时爬、道具、角度、力度只在本机预演，按"发射"把这一回合（爬动序列、道具、角度、力度、朝向）打成一条消息发给房间；
  房间验过、结算完广播结果（这一回合的操作和下一回合的风），所有人按它放动画。30 秒没出手算弃权；掉线 60 秒后电脑托管，回来交还。
  顶栏有倒计时，轮到别人写"某某正在瞄准…"，名牌上挂"掉线""电脑代打"。
- 结算：房主"再来一局"大家回到同一个房间（选择都留着，要重新准备）；"回房间"先回房间页；"大厅"离开房间。
- 房主：开房的人。准备、结算时房主掉线满 60 秒，房主交给下一个坐着的真人（按座位顺序），回来不收回；点"大厅"离开也马上交出去；对局中不交。
- 刷新、断网、切后台：kit 的 `RoomClient` 自动重连，回来拿全量快照、整局重放；`danli.room` 记着最近的房间码，刷新后自动回房，点"大厅"、房间关了就删掉。
- 实现（DESIGN.md 5.6、仓库根 docs/platform-backend.md 第 4 节）：
  - 规则 `src/net/rules.ts`（kit 的 `RoomGame`，房间和页面共用的纯函数）。房主一进房就让 kit 开局，之后准备、对局、结算都是游戏自己的阶段（kit 一直"在打"），
    所以再来一局还在同一个房间；kit 的 6 个座位只代表"房间里的人"，两队的位子、对阵、地图、小动物、武器、准备都是不轮流的操作（kit 的 `free`），房主在房间里随时改；
  - 一回合一条 `act`（`turn` 或 `pass`），房间用规则核心逐项验证（`net/replay.ts` 的 `stepRec`），不合法回固定短码（`not_your_turn`、`angle`、`tired`、`steep`……）；
  - 每一手打完房间先"停一会儿"（kit 的 `pause`），时长按这一手的动画算（`net/anim.ts`，页面的动画不超过它），停够了下一个人的 30 秒才开始；
    炮弹飞行按 1.6 倍时长放（`anim.ts` 的 `FLIGHT_SLOW_PCT`，多出来的最多 1 秒：`FLIGHT_EXTRA_MAX`）；一手连扔好几轮时从第 3 轮起放快（3 倍，往后每轮翻一倍：`volleyPace`；
    飞、爆炸、掉血、往下掉都快，出局、换人不快）。单机和好友房的画面、房间的停顿用同一套数（`flightMs`、`fallMs`）。
    电脑对打 3v3 一手中位 9.3 秒、九成九 16.8 秒，最长约 19.7 秒（三岔 + 连发 +1 + 连发 +2 满力往上打），`test/net.test.ts` 卡住不超过 20 秒；
  - 电脑的回合交给一个没人坐的 kit 座位，kit 马上调 `ai`，房间用联机档电脑（`ai/online.ts`）想一步、结算；一次只算一个（`maxAiBatch` 1）。kit 座位全坐满真人时借房主的座位、1 秒后按超时由电脑出；
  - 视图不带种子：开局设置、出生点、先手、第一回合的风、每一回合的操作和下一回合的风，页面自己重放（`net/replay.ts` 的 `startOf`）；
  - 服务端的地形网格不进存储：存角色这些小东西和挖过的坑（x、y、半径），房间被驱逐后按地图加坑重建，内存里按对象缓存；
  - Worker：`POST /games/danli/rooms` 开房（`acceptCreate`），`/games/danli/rooms/<码>/ws` 进房（`acceptJoin`），房间类 `worker/room.ts` 的 `DanliRoom`，计量是 kit 的 `RoomMeter`；
  - 每一步写入不超过 2 行（test/room-do.test.ts 在 Node 里跑真的 kit 房间断言），快照上限 20 KB（test/net.test.ts）；
  - 准备、结算阶段房主算"该出手的人"（时限一天，在线时到不了）：他掉线满 60 秒 kit 转托管、调 `ai`，规则回 `handoff` 把房主交出去；
  - 服务器 CPU：每一步 p99 ≤ 3 ms（`npm run cpu`，见下面"数值"；CI 上放宽到 8 ms）。

本地联机（不要 Cloudflare 账号）：

```bash
npm run dev:worker   # 打包页面，本机起 Worker（wrangler dev，端口 4179），房间、计量都是本地的 Durable Object
                     # 打开 http://localhost:4179/games/danli/?name=小A 开房，另一个浏览器（或无痕窗口）打开复制的链接，加 &name=小B
```

没有平台时是 kit 的独立模式：每个浏览器一个游客身份，昵称取地址上的 `?name=`；`npm run dev`（vite）只有单机，开不了房。

## 规则要点（数值都在代码里一处）

- 世界 3000×780，地形网格每格 4×4（`core/terrain.ts`）；格子存材质，地图自带的坑和井口边上的格子打个"焦"标记（画坑边用；武器的坑不打，焦痕另画）。悬空的地断开以后不塌落。
- 炮弹：位置、速度以 1/1024 单位存，每帧 `vx += 风 × 6`、`vy += 256`（`core/physics.ts`）；力度 1 点 = 初速度 256，满力 45° 大约打 2500 远。每帧的位移切成不超过 2 单位的小段查碰撞。
- 地图（`core/mapData.ts`、`core/mapData2.ts`，美术交付）：11 张，画本都薄，每块地有材质（材质码写进格子低 7 位，规则上都一样；50 种，1–50 号）。
  寿司长台 3600 宽（别的 3000），远景烘焙（地图宽 + 1400）、镜头、全图、缩略图、出生点的间距都按地图宽算。
- 出生点：每张图一张候选表（只写 x，至少 10 个：前五张 11 个、早餐吐司桥 10 个；脚下都厚 80 以上），开局用 `open` 洗牌、两队交错挑，离对手至少"地图宽 ÷ (人数 + 1)"、离队友至少 240（`core/rules.ts` 的 `pickSpawns`，算法见 DESIGN.md 第 3 节）；开局朝着最近的对手。
- 武器（`core/weapons.ts`）：8 把，攻、防、爆炸范围、角度照 DESIGN.md 2.6；爆炸范围三档：小（伤害半径 22、挖 19）、中（30、26）、大（40、35），挖坑照包子蒸笼的比例。
  特技还没做。基础伤害是调平用的（设计表里没有）：包子 36、西瓜 31、球拍 39、萝卜 36、烟花 36、拖鞋 68、飞盘 38、奶茶 34，见下面"数值"。
- 爆炸：以命中点为坑心、按这把武器的坑形挖（`core/craters.ts`，美术交付，整数运算，只扫 ≈1.3 倍挖坑半径的方框；坑形固定，不随方向转）：
  包子圆、西瓜又宽又平的椭圆、球拍 2 格一块的网格方块、萝卜又窄又深的竖坑、烟花六角星、拖鞋鞋底印、飞盘扁长浅槽、奶茶圆坑带一道往下的流痕。
  直接打中人时坑心放在他身子中间，坑一定挖到他脚下。伤害 = 基础 × (70 + 5 × 攻)/100 × (100 − 3 × 对方防)/100 × 距离衰减（到半径边上一半）× 道具倍率，整数，按圆形的伤害半径算，不跟坑形走。
  命中不推人（0.3.0 起）：脚下的地被挖空了就往下掉，掉出画本只靠挖。
- 体力：每回合 100，爬和道具共用（`core/rules.ts`）。爬一步 4（一格）扣 2，往上每 2 单位高差多 1，一步最多上下 12；前面是空的就停住。
- 血量上限 180（`core/rules.ts` 的 `MAX_HP`）。
- 道具（`core/items.ts`，0.3.0 常用道具任意组合）：一回合能选多个、同一个能选多次，只看体力；三岔、加力 50% 一回合最多 1 个（规则里显式校验）；纸飞机独占。
  轮数不另设上限（体力决定，100 体力最多 7 轮：三个 +2），规则里只留防异常的 10 轮。
  轮数 = 1 + 连发数（+1 算 1、+2 算 2），选了三岔每轮 3 颗；每颗伤害按总轮数取（1–10 轮：100 / 54 / 37 / 29 / 23 / 20 / 17 / 15 / 14 / 13%），三岔每颗再乘 35%，
  加力相加后乘到每一颗上（向下取整的万分比）。一手不止 1 颗时每颗的挖坑半径打 98 折（取整：包子 26 → 25、西瓜 35 → 34、拖鞋 19 → 18），伤害半径不变。
  价钱：连发 +1 18、+2 30、三岔 52，加力 10% 16、20% 30、50% 72（加力 50% + 20% 是 102，买不起）；特殊道具纸飞机 60（0.3.1 起每局不限次数）、锅盖 30（每局 2 次）。三岔 + 连发 +1 + 连发 +2 正好 100。
  一轮一轮来（前一轮的坑、掉落会影响后一轮，自己出局了就不再扔）；三岔一轮三颗（角度 −6°、0、+6°，夹在 0–90°）同时飞、按落地先后炸（一样快按角度从小到大）。
  地形一手只复制一次，每颗在这份上挖。
  纸飞机落地不炸、人瞬移到落点上方第一个站得下的地方，撞到人就落在他旁边最近的空位，飞出画本作废；不能和别的道具一起用。
- 掉落：脚下（中间和左右各 3）都没地就往下掉；摔超过 60 每 10 扣 1、最多 20；掉到底边或出了左右边就出局。
- 对阵：两队各 1–3 人（`setupError` 检查），座位顺序就是开局设置里 players 的顺序（蓝队我、队友，再黄队）。
- 出手和轮：两队交替出手、队内按座位轮，出局的跳过；还活着的每个人都出过一次手算一轮（人少的那队一轮里有人出手两次），打满 15 轮按全队剩余血量总和定胜负（`MAX_ROUNDS`；开局设置的 `maxRounds` 只给模拟器用）。
  `turn` 是第几次出手（风和电脑的随机流按它取），`round` 是第几轮，顶栏写"第 N 轮 / 15"。
- 电脑（`ai/index.ts`）：只朝对手那边打；伤到自己扣 1.5 倍、伤到队友扣 2 倍。人物（`ai/personas.ts`）：橘子包子蒸笼、团团奶茶炮、企企弹弹球拍、柴柴西瓜投石器、兔兔冲天烟花筒、鼠鼠萝卜钻（准备房间里电脑座位的默认武器）。

## 性能

- 远景整张、地形每 256×256 一块，都是烘焙好的画布，放在"镜头那一层"里按世界坐标摆好；镜头平移缩放只改这一层的 CSS transform（交给合成器），每帧不重贴；
  炸到哪块只重画哪块。上面一张透明画布每帧只画纸边、角色、炮弹、特效和名牌，JS 一帧约 1–2 ms。
- 焦痕（DESIGN.md 2.3.1）：每块地形另有一张只增不减的焦痕层（炸到过才建），新坑挖完只往相交的层上画这一个坑一次；重烘焙那一块时裁到有地的轮廓里贴上去，
  不会每次重烘焙都把所有坑重画一遍。读档、重连、跳到最新的局面时从地图原样按坑的先后重来一遍（先挖再画），和一手一手放出来的一样。
- 弹道的镜头（DESIGN.md 2.2.1，只是画面）：轨迹出手时已经算好，镜头把所有炮弹的整条弹道（上下再多留一点给人和爆炸）框进看得见的那一块，缩放 0.5–1；
  框不下时跟着第一颗还在飞的炮弹：炮弹在画面中间的"活动框"里（横着往飞的方向留空间，竖着中线上下 0.32）镜头不动，出了框才推着镜头走。
  炮弹位置在 path 的两步之间插值。
- 角色贴着地面倾斜（DESIGN.md 2.4，只是画面）：脚底左右各 12 单位处的地表算坡度，最多 ±35°，每帧缓过去；名牌、箭头、角度盘不歪，瞄准仍按水平线算。
- 画布渲染倍数封顶 2（手机按像素比 3 时也按 2 画）；远景按 0.4 倍烘焙。
- 实测（`npm run perf`，无头 Chrome、关 GPU 的软件渲染，手机横屏 844×390）：不降速时跟随、拖动、跟炮弹都是一帧 16.7 ms；
  CPU 降速 4 倍、像素比 3（画布按 2 画）时一帧约 50 ms（p95 约 67 ms），像素比 1.5 时约 33 ms，像素比 1 时中位 16.7 ms；
  每帧 JS 只花 1–2 ms，其余是软件合成整屏透明画布的时间（把上面那张画布或下面那一层任意藏掉一张，降速 4 倍也是 16.7 ms）。真机由 GPU 合成，还要在手机上实测确认。
- 局末坑多（0.3.0，`npm run perf` 的后半段：3v3 打到第 12 轮的存档，86 个坑、6 把武器，同样降速 4 倍、像素比 3）：
  读档时重建焦痕 471 ms（建了 28 张焦痕层）、首次烘焙 24 块共 490 ms；之后跟随、跟炮弹的帧和开局一样（中位 50 ms、p95 67 ms，画一帧中位约 2 ms）；
  新坑画一次焦痕约 6 ms、跟着重烘焙 4 块平均约 5 ms 一块。焦痕层和地形块一样大（渲染倍数 2 时一张约 1 MB），28 张约 30 MB。

## 监控

照 docs/platform-backend.md 第 16 节接平台的监控：
- `GET /games/danli/health` 回 `{"ok":true,"version":"<package.json 的 version>"}`（不缓存）：排在 Worker 路由最前面，不过登录闸门、不读存储、不问平台，单独部署也能访问；版本号从 `package.json` 导入，打包时内联；
- `wrangler.jsonc` 开着 `observability`（Workers Logs）；
- 页面入口调一次 kit 的 `reportErrors`（`arcade-kit/report`），没人接住的报错报给平台的 `/api/client-error`：只带报错、调用栈、路径、游戏和版本。

## 部署

`wrangler.jsonc` 是独立配置（静态资源 `ASSETS`，好友房的 Durable Object `ROOM`（`DanliRoom`）、`METER`（kit 的 `RoomMeter`），迁移 `v1` 用 `new_sqlite_classes`；
不写平台绑定和 `GATE`）：`npm run deploy` 能单独部署成一个游客就能玩（好友房也能开）的游戏。
`KIT_QUOTA` 还没写：部署白名单（仓库根 `tools/deploy-allowlist.json`）里还没给 danli 放行这个变量，现在用 kit 的默认门槛（每人同时 1 个、每天 6 个房间；写入 6 万停开新房、8.5 万收场）。
本站部署时由维护者的部署工具补平台绑定、`GATE`、路由（见仓库根 docs/new-game.md 第 4、5 节）。还没有接平台的云存档和排行榜。
