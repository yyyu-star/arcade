## 0.23.0

电脑版排版第一批：钱包、排行；排行页加上各游戏总榜。

- **电脑排版的骨架**：≥1100 内容区从 1120 放宽到 1280；做好了电脑版的页面（这次是钱包、排行）≥960 主区不再是中间 520 的一窄列，分两栏；960 以下照旧单列。读取中的"正在读取…"换成灰色占位条（骨架屏），不跳不闪。

## 0.19.2

第三轮安全审计，平台三条（`docs/platform-backend.md` 5.1、5.4、7.2、7.3、15.6 同步改）：

- **中：全站每小时的登录、找回名额只算用户名存在的尝试**。原来查用户名之前就计数，拿不存在的用户名换十来个 IP 段就能让全站一小时登录（300 次）、找回（100 次）都 429。
  选的是"挪到用户名存在之后"而不是"按 IP 段加权"：撞库要猜的是真账号，这部分照旧全算，防撞库不变弱；乱填的用户名伤不到账号，由每个 IP 的上限和令牌桶管；
  加权只是抬高成本、段的大小也不好定（移动网络多人共用出口）。现在要占满全站名额得知道很多真用户名，每个错 5 次就锁。
- **低：算密码之前先占一次尝试**（`reserveAttempt`，带条件的 UPSERT，锁着时 0 行、429），对了再清零：锁到期那一刻并发打进来的一批只有一个能验密码（原来全都能）。
  登录成功因此多写 2 行（占位 1 + 清零 1），4 → 6；失败行数不变。
- **低：用户名不存在也白算一次哈希**（`burnPasswordHash`），响应时间和密码错一样，看快慢猜不出用户名在不在。
- **低：每天的清理每一段单独 try/catch**，一段出错只跳过这一段。
- 测试：全站名额不被不存在的用户名耗掉（登录、找回各一个）、满了以后照样 429、0 行；并发 20 个只有 1 个 401；登录成功 6 行；
  不存在的用户名耗时不低于密码错的一半（10 万次迭代）；清理中间一段抛错后面照清。反证：这 7 个在原来的代码上都失败。

## 0.10.20

开源整改，线上行为不变（同一个域名、同一个库）：
- 仓库里不再写正式站的域名和 D1 的 id。正式部署时由工作流从 GitHub `production` 环境的 secret 注入：
  域名用 `--domain` 挂成自定义域名，`SITE_ORIGIN` 用 `--var` 注入；D1 的 id 由 `tools/deploy-config.ts` 写进一份不进 Git 的部署配置，迁移和部署都用它。
  id 没设或不像 id 时直接失败，不会让 wrangler 自动新建空库。
- `SITE_ORIGIN` 改成可选：设了照旧只认这个主机名；没设（一键部署）按请求自己的地址，写请求的同站检查照样挡得住跨站。
- 支持 Deploy to Cloudflare 一键部署：`.dev.vars.example` 列全 Secret 并写明说明，`package.json` 加 `cloudflare.bindings` 说明，
  `npm run deploy` 先跑 D1 迁移再部署；部署后绑自定义域名、建第一个管理员的步骤写在 README。
- 管理命令行工具（`npm run admin`）不再有默认地址，必须用 `--base` 或环境变量 `ARCADE_BASE_URL` 给。
- 恢复码图片上的站点地址改成当前页面的地址（`location.host`）。
- 测试里的域名换成 `game.example.com`；文档和注释去掉内部分工的说法；`package.json` 加 `"license": "MIT"`。
- 搬家前旧仓库的 PR 编号不再写成 `#NN`（公开仓库里会被链接到同号的无关 PR）：能靠版本号说清的删掉，其余写成"旧仓库 PR NN"。
