# 好友房聊天（设计稿，kit 0.18.0 起）

> 范围以仓库根 `docs/social.md` 3.1 节为准（只在好友房、一条最多 30 个字、服务端限速和过滤、不落库不进录像、复用现有屏蔽，平台的屏蔽名单也生效）。
> 本文写 kit 这一层怎么做，游戏怎么接；审过再写代码。

## 0. 结论

- 好友房里入座的真人能打字，旁观的人能看不能发，电脑不说话（电脑照旧只发短语）。
- 单机也能聊（0.18.1，所有者要求聊天通用）：`localChat` 过同一套过滤和限速，只在本机自己头像旁显示自己说的，不发到任何地方、不存；电脑不读、不回（公平底线不变）。
- 一条 ≤ 30 个字；每人 3 秒一条、每分钟最多 10 条；链接、手机号、微信号、QQ 号样式的整条拒发（告诉发的人为什么），脏话打码后照发。
- 房间只转发、不存：不写 Durable Object 存储、不进快照和重连补发、不进任何对局记录或录像；房间关了就没了。
- 显示：发言人头像旁冒气泡（和短语气泡同一个样式），"互动"面板里多一个"聊天"页：输入框 + 最近 30 条（只在本页内存里）。
- 屏蔽：kit 现有的"屏蔽他 / 全部屏蔽"同样挡聊天；平台的屏蔽名单（social.md 3.1 要求生效）要平台加一个 RPC，见第 6 节（顺序需要主线定）。
- 游戏要显式打开（`RoomGame.chat = true`），不开的游戏行为完全不变。

## 1. 协议

| 方向 | 消息 | 说明 |
|---|---|---|
| 上行 | `{ t: 'chat', text: string }` | 只有入座的人能发 |
| 下行 | `{ t: 'chat', seat: number, text: string, masked?: true }` | 广播给房间里所有"认聊天"的连接（含旁观、含发的人自己）；`masked` 表示打过码 |
| 下行 | `{ t: 'error', code }` | 被拒时只回给发的人，见下表 |

- 和短语一样**不进 `DownMsg`**：`RoomClient` 加 `onChat(seat, text, masked)`，不进 `onMessage`，游戏按 `DownMsg` 写的代码不用改。
- **兼容旧页面**：新版 `RoomClient` 连接时在地址上带 `chat=1`，房间把它记进这个连接的附件，只给带了的连接发聊天。
  旧页面不带，就收不到 `chat`（它们不认识这个消息，可能会出错）；旧页面发不了聊天。所以**不加 `PROTOCOL_VERSION`**，正在打的房间不受影响。
- `welcome` 多一个可选字段 `chat?: { ms, perMin, max }`（房间实际用的节奏和字数），页面按它本地先挡一遍、按钮置灰，不靠被拒。

被拒的 code（`CHAT_ERRORS`，只回发的人）：

| code | 什么时候 | 页面怎么说 |
|---|---|---|
| `chat_off` | 这个游戏没开聊天 | 不显示输入框，碰不到 |
| `not_seated` | 旁观、没入座 | 输入框不显示 |
| `room_over` | 房间打完了 | 输入框置灰 |
| `chat_empty` / `chat_too_long` | 去掉空白后为空 / 超过 30 个字 | 本地就挡住，不会发 |
| `chat_too_fast` | 3 秒内第二条，或这一分钟满 10 条 | "说慢一点"（按钮倒计时） |
| `chat_blocked` | 像链接、手机号、微信号、QQ 号 | "不能发链接和号码" |

## 2. 过滤（服务端，`src/chat.ts`，纯函数，房间和页面都 import）

顺序：规整 → 判长度 → 判导流 → 打码。页面发之前跑同一个函数给即时提示，房间收到再跑一遍（以房间为准）。

1. **规整**：`NFKC`（全角转半角、兼容字符归一）；去掉控制字符、零宽字符、方向控制符；连续空白并成一个；去掉首尾空白。
2. **长度**：按码点数（`Array.from`），≤ 30；为空回 `chat_empty`。
3. **导流整条拒发**（`chat_blocked`），先把常见的绕法还原再判：
   - 去掉夹在中间的空格、点、横线、下划线（`1 3 8-0013 8000` → `13800138000`），中文数字（〇一二三四五六七八九、幺）转成阿拉伯数字；
   - 链接：`http`、`www`、`://`，或者"字母数字 + 点 + 常见顶级域"（`.com .cn .net .org .top .xyz .cc .io .me .vip` 等，`。`、`点` 当成点）；
   - 号码：连续 ≥ 7 位数字（手机号、QQ 号、座机）；
   - 微信 / QQ 样式："微信、威信、薇信、vx、v信、wx、weixin、qq、扣扣、企鹅、加我、私聊、加群、群号"后面跟着 ≥ 5 位字母数字。
   - 误伤的边界：比分、牌面这类短数字（"10 张"、"打 2"、"A×2"）都不到 7 位，不受影响；有测试守住常用短语不被拒。
   - 筹码金额（主线审时加）：标准千分位写法（`1,000,000`，前后不挨着数字和逗号、总共 ≤ 10 位）不算号码；拒发号码时提示"不能发号码，金额请写成 1,000,000"。
     11 位的手机号写成千分位（`13,800,138,000`）、乱分组的（`138,0013,8000`）照样拦。
   - 电话、手机两个词不进第 3 条的叫法：号码本身 ≥ 7 位就拦了，放进去反倒误伤"手机快没电了 hello"。
4. **脏话打码**（`masked: true`）：词表放 `src/chat-words.ts`，命中的每个字换成 `*`，照常发出去。
   - 词表按"短、常见、无歧义"收（几十个），用规整后的文本、忽略大小写匹配，中间夹空格、符号的也认；
   - 游戏可以加词（`RoomGame.chatWords`），不能删 kit 的；
   - 不拒发：打码后话还能说，拒发会让人换着法子绕。
5. kit 里不出现任何游戏的名字和概念；词表不针对真实个人（仓库根 AGENTS 第 4 节）。

## 3. 限速和额度（房间）

- 每个座位两道：令牌桶 `chatMs = 3000`、`burst = 1`（3 秒一条），加一个滚动一分钟的计数 `chatPerMin = 10`。
  两个数照短语的做法，代码里有默认值，游戏 `wrangler.jsonc` 的 `vars.KIT_QUOTA` 写了 `chatMs` / `chatPerMin` 就以那里为准（不用发版就能调）。
- 聊天和短语是两个桶，互不占用。被拒的不消耗令牌。
- 入站计数照旧：每条聊天和别的上行消息一样记进这个人的那一份（`maxInboundShare`），刷不出房间一生的上限。
- 不写存储（0 行），不改 `seq`，不碰闹钟——和短语一样，"每步 ≤ 2 行"的规矩不受影响。
- 下行体积：一条 ≤ 30 字 × 广播人数，比一手牌的状态小得多；不另设上限。

## 4. 不落库、不进录像

- 房间：`chat()` 只校验、过滤、广播，不进 `st`，不进快照（`welcome` 里没有聊天记录，重连或中途进来的人看不到以前说的）。
- 页面：最近 30 条只放在 `TableFun` 的内存里，不写 localStorage / IndexedDB / 云存档；关页面、换房间就清空。
- 游戏：聊天不进对局日志、复盘、分享卡、动态（`docs/social.md` 的名场面只用公开出牌数据，照旧）。kit 的架构测试加一条：`chat` 相关代码里不出现 `storage.`、`localStorage`、`indexedDB`。

## 5. 界面（`table-fun.ts` + `table-chat.ts`，0.19.0 重做）

所有者 2026-10-18：聊天太简陋、不显眼，电脑上气泡太小。0.19.0 起聊天不再只藏在"互动"面板的页签里。

- **电脑**（可见区宽 ≥ 960 且高 ≥ 560，`chatMode`）：牌桌一角常驻聊天框。标题行"聊天"、"弹幕：开 / 关"、"展开记录"、"收起"；
  下面是最近几条记录（按内容高度，最少两行、最多五行；展开后最多半屏、30 条）、一排快捷短语（横向滑动，右边渐隐）、输入框（点一下就能打字，回车发送）。
  收起后变成一个"聊天"小按钮，有新消息时带红点。位置：游戏用 `chatDock()` 指定；不给就在四个角里挑不压手牌、按钮、头像、名牌、`center` 的那个，
  上面两个角从屏高 9% 往下（各游戏的顶栏在那一条）。kit 不知道牌墙、弃牌区在哪，**游戏接入时用 `chatDock` 或 `center` 传准**。
- **手机**：单独一个"聊天"按钮（和"互动"按钮一样大、挨着它，按 `placeBeside` 先右后左再上下；游戏可以用 `chatButton()` 指定，挤的牌桌最好给），有未读红点。点开是一条输入条：
  快捷词一排、输入框、发送、"记录"（打开互动面板的聊天页看 30 条）、✕。输入条贴在手牌和操作按钮的上面（`barBottom`），键盘弹起时站到键盘上面。
- **快捷短语**：就是游戏的短语表，点了按短语发（走互动的发送通道和冷却，没开打字聊天的桌也能用）；短语和打字一样进记录、飘弹幕。
- **弹幕**：所有人说的话（含自己、含短语）从右往左飘，自己的金边高亮。轨道（`danmakuLanes`）在弹幕区里按 4px 一档找不压手牌、按钮、头像、名牌、
  `center`、聊天框、正在显示的气泡的横条，从上往下取、互不重叠；一条都找不到时只走压得最少的那一条。弹幕区默认是屏幕 8%–58%，
  上沿压到最上面一排座位（对家那排）的头像和名牌下沿以下（顶栏和对家名牌不被横穿），不够两行往下放宽；游戏可以用 `danmakuArea()` 指定。弹幕在效果层最底下，气泡、表情、道具永远盖在它上面。
  同屏最多 12 条（手机 6 条），满了排队最多 8 条，再多丢最老的；所有条同一速度（横穿一屏约 8 秒），后一条追不上前一条。只动 transform。
- **弹幕开关**：聊天框标题行、互动面板聊天页各有"弹幕：开 / 关"，游戏设置里可以用 `fun.danmaku()` / `fun.setDanmaku(on)` 接同一份。
  默认开；系统设了减少动态效果（`prefers-reduced-motion`）或省内存模式（游戏传 `lite()`，不传看 `navigator.deviceMemory ≤ 2`）时默认关。关了只有气泡。
- **气泡**：字号跟着屏幕（`chatFont`：电脑 18–22px，手机 ≥ 15px），一行约 16 个字、最多两行折行，不再一行省略号截断；聊天的停 5 秒，同一个人连说两条后一条顶掉前一条。
  位置（`placeBubble`）避开"互动"按钮、聊天框、`center`、各家名牌（`FunSeat.plate`）、别家头像和别的气泡。**名牌由游戏传**，不传就只避头像。
- **记录**：最近 30 条，只在内存里；名字按座位配色（`seatColor`）。
- **设置存哪**：弹幕开关、聊天框收没收起、记录展没展开存在 `prefsKey`（默认 `<storageKey>.chat`，必须是 `<游戏id>.<名字>`，构造时检查），遵守存储前缀规则。
- **手机键盘、点按区**：输入框 16px（iOS 不放大页面）；可点区域 ≥ 44 CSS 像素。
- **开关**："聊天：开 / 不看"（`chatEnabled`）照旧：不看时没有聊天框、聊天按钮和弹幕，别人的气泡、记录都不显示。

## 6. 屏蔽

- **kit 现有屏蔽**（本页、按房间、`sessionStorage` 的 `<id>.fun.blocked`）：屏蔽了的座位，聊天气泡和记录都不显示；"全部屏蔽"同样适用。纯本地，对方不知道。
- **平台的屏蔽名单**：页面拿不到（`GET /api/friends` 不返回屏蔽名单，也拿不到同桌人的 userId），只能在房间服务端做。方案：
  - 平台加一个服务绑定 RPC：`ARCADE.blockedAmong(userIds: string[]): Promise<[blocker, blocked][]>`，只查这几个人之间的屏蔽，读 0 行写 0 行以外不碰别的；
  - 房间在座位绑人（开打、换人接管）时问一次、缓存在内存里（不写存储）；转发 A 的聊天时，跳过屏蔽了 A 的人的连接（A 自己照常看到自己发的）；
  - 平台没有这个 RPC（旧平台、单独部署）时跳过这一步，只剩 kit 本地屏蔽。
  - **主线定了 B**（2026-10-17）：0.18.0 只有 kit 本地屏蔽，平台 RPC 合了以后 kit 小版本接上，游戏不用改。原来的两个方案：social.md 3.1 写了平台屏蔽名单也生效，所以要做；问题是先后。A：平台先出 RPC，kit 一次接齐（多等一个平台 PR）；
    B：kit 第一版先上本地屏蔽、留好"没有 RPC 就跳过"的口子，平台 RPC 合了以后 kit 小版本接上（游戏不用改）。我建议 B——好友房的人都是互相给过房间码的，屏蔽过的人一般不会同桌，不值得让聊天整体等平台。

## 7. 游戏怎么接（德州先接，然后掼蛋、麻将）

1. 房间类：`chat = true`（可选 `chatWords`）。
2. 页面：`new RoomClient({ ..., onChat: (seat, text, masked) => fun.chat(seat, text, masked) })`；`TableFun` 传 `chat: (text) => client.chat(text)` 和 `chatEnabled`。
3. 设置面板加"聊天：开 / 不看"；隐私说明加一句"好友房的聊天不保存，房间关了就没了"。
4. 冒烟：两个页面进同一个房间，一边发一条正常的、一条带手机号的、一条带脏词的，另一边看到第一条、看不到第二条、第三条打码；旁观的页面看得到发不了。

## 8. 测试（kit）

- `test/chat.test.ts`（纯函数）：规整（全角、零宽、空白）、长度、链接 / 号码 / 微信 QQ 的各种绕法、常用短语和牌面短数字不被误伤、打码。
- `test/room.test.ts` 加一组：只有入座的能发、旁观收得到、没带 `chat=1` 的连接收不到、限速两道、被拒不耗令牌、不写存储（存储调用次数为 0）、不进 `welcome`。
- 架构测试：`chat.ts` 不碰 DOM、不用时间和随机；聊天代码不出现存储 API。
- 改了房间行为的都做反证（kit AGENTS）。

## 9. 不做

- 私聊、语音、图片、表情包上传；聊天记录导出；举报（第一版靠屏蔽）。
- 电脑读真人打的字、回复自由文字（单机能打字，但只是自己看；电脑只发短语，公平底线不变：电脑不读真人说的话）。
- 服务端存任何聊天内容、做内容审核后台。
