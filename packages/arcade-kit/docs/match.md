# 快速匹配（设计稿，kit 0.19.0 起）

> 所有者 2026-10-18 要求：好友房之外，能在游戏里直接匹配别人。本文写 kit 这一层怎么做、游戏接什么、第一版不做什么；审过再写代码。
> 房间规范以仓库根 `docs/platform-backend.md` 第 4 节为准，聊天以本目录 `chat.md` 为准，钱包和档位以仓库根 `docs/economy.md` 为准。

## 0. 结论

- 入口：游戏主页 / 选档页加一个"快速匹配"，选好档位后进入排队。同一个游戏、同一个档位的人排在一起；娱乐和实盘分开排，档位不同不凑。
- 等多久：最多 **15 秒**（`waitMs`，游戏可调）。凑满一桌立刻开；到 15 秒时：
  - 排着的真人 **≥ 2**：开一个房间，真人入座、空位电脑补，马上开打；
  - 只有自己 **1 个**：不开房间，直接转成本机单机（同一档位，和现在点"单机"一样），不占任何联机额度。界面说"现在没人在排，先和电脑打"。
- 开出来的是普通的联机房间（现有 `GameRoom`，规则、计时、托管、钱包、互动都不变），只是没有房主、不用点"开打"，房间码不给人看。
- **不新建 Worker**：每个游戏现有的 Worker 里加一个 Durable Object 类（排队），房间仍用现有的房间 DO。
- 陌生人桌：快捷短语和表情照常；**打字聊天默认关**，自己在设置里打开"和陌生人打字聊天"才收发；"屏蔽他"照常可用。
  平台屏蔽名单生效的方式是"屏蔽过的人不会被排到一桌"，要平台出一个 RPC（第 5 节）；平台没出之前只有本地屏蔽。
- 计量照旧：排队本身 0 行存储写入；每张匹配桌对每个真人都占一个开房名额（同时 1 个、每天 6 个这套），写入走同一个计量。

## 1. 流程

```
浏览器                    游戏 Worker                 排队 DO（每个档位一个）             房间 DO
  │ 点"快速匹配"(档位 t)     │                            │                                   │
  │── WS /match?t=… ───────▶│ acceptMatch：认人、查 Origin │                                   │
  │                         │ 查计量（有在打的房间就回码）── RPC kitEnqueue ─▶│ ctx.acceptWebSocket，附件记人  │
  │◀──── {t:'waiting', n, left} ───────────────────────────│ 人数变了就推一次                    │
  │                         │                            │ 满一桌或到 15 秒且 ≥2 人：           │
  │                         │                            │ 逐个向计量占名额 → kitCreateMatch ─▶│ 建房、记下这几个人的座位
  │◀──── {t:'matched', code} ──────────────────────────────│ 关掉这几条排队连接                  │
  │── 现有的 RoomClient 进房（acceptJoin）────────────────────────────────────────────────────▶│ 全到齐或 20 秒后自动开打
  │                                                                                         │ 没来的座位电脑补
  │◀──── {t:'solo'}（只剩自己、到 15 秒；或联机忙）── 页面转本机单机                              │
```

- 排队连接用 WebSocket（休眠），不用轮询：人数变化服务端推，用户关页面就自动出队，不用另外"退出排队"的请求。
- 页面显示："正在找人 · 已有 2 人 · 还剩 9 秒"，下面一个"取消"（关连接）和一个"不等了，和电脑打"（转单机）。
- 匹配到以后，页面用现有的 `RoomClient` 进房，和好友房同一套界面，只是不显示房间码、邀请、叫人这些好友房的按钮。

## 2. 排队 DO（kit：`arcade-kit/match` 的 `MatchQueue`）

- **一个档位一个实例**：`idFromName('<档位 key>')`。现在一天几个人，一个实例足够；档位 key 由游戏给（如 `real-2`、`fun-normal`），排队 DO 只当字符串比较，不认识档位的含义。
- **0 行存储**：排着的人就是 `ctx.getWebSockets()`，附件里放 `{ userId, name, since }`（4.1 一样只放这些）。DO 被驱逐后连接和附件还在，名单不丢。
- **一个闹钟**：最早那个人的 `since + waitMs`。只在"队里从空变成有人"或"凑桌后还有剩下的人"时设，只往早挪（4.1）。每次醒来写 1 行（闹钟）。
  一天几十次排队，写入可以忽略。
- **凑桌**：按排队先后取前 `seats` 个人（`seats` = 这个档位一桌最多几个真人，游戏给）。座位顺序随机打乱（`crypto.getRandomValues`，不在规则核心里），由房间按现有规则补电脑。
  游戏有特殊要求（比如掼蛋两个真人坐对家还是对面）用 `matchSeats(n)` 钩子给座位号，不给就随机。
- **同一个人只排一次**：同一个 userId 再连进来，旧连接 4001 让位（和房间一样）；在别的档位排着的，由游戏 Worker 在入队前看不出来，第一版接受（同一个人两个标签页各排一个档位，最多凑到两桌，各占一个开房名额，名额管住了上限）。
- **限速**：每个连接沿用令牌桶（4.6，每秒 5 条），排队连接其实只收不发；每人每小时入队 ≤ 30 次（内存里记，被驱逐就清零，接受），超了 4029。
  没入队的连接不存在（入队就是连接本身），所以没有"没入座的连接满了"这一类。队长上限 200，满了回"人太多，稍后再试"（1013），挡住刷连接。
- **不碰牌局**：排队 DO 不 import 规则、不读房间状态、不知道谁赢谁输。电脑补位、公平底线全在房间里，和好友房一样。

## 3. 房间的改动（kit：`GameRoom`）

- 新 RPC `kitCreateMatch(code, players: Identity[], options)`：只有排队 DO 调（内部地址，不进 `exports`，和 `kitCreate` 一样走 `internal.ts`）。
  建房时把这几个人预先记在座位上（`kind: 'human'`、`awaySince` = 建房时间），状态里记 `match: true`、没有 `host`。开房写入和现在一样（4 行：建表 2 + 状态 1 + 闹钟 1）。
- **自动开打**：预定的人都连上就开；`matchJoinMs`（默认 20 秒）到了还没来的座位换成电脑，照样开。用现有的那一个闹钟（4.1），开打这一步写 ≤ 2 行。
  开打以后的一切（30 秒一手、掉线 60 秒托管、收回、寿命、入站额度）都是现有逻辑。
- **只有被排进来的人能入座**：`match` 房间不接受别人进来坐下（`seat_taken`）；房间码不给页面显示，也就没有旁观。有人中途离开，座位交给电脑（现有的离座逻辑），不再补真人。
- **再来一局**：沿用游戏现有的续局（同一房间、同一批人）；有人走了就电脑补。不回到排队。
- 没有房主：现有只给房主的操作（开打、改选项）在 `match` 房间里都不需要，统一回 `not_host`。

## 4. 计量和限速（照 platform-backend 第 4 节）

| 事 | 存储写入 | 计量 |
|---|---|---|
| 入队、出队、人数变化推送 | 0 | 不占名额；只在 `acceptMatch` 时问一次"这个人有没有在打的房间"（只读） |
| 排队闹钟醒来 | 1（闹钟） | — |
| 凑出一桌 | 房间 4 行 + 每个真人计量 2 行 | 每个真人各占一个开房名额（`roomsPerUser` 同时 1 个、`dailyRoomsPerUser` 每天 6 个，`KIT_QUOTA` 可调）；全站 `busyWrites` 照旧 |
| 匹配桌开打以后 | 和好友房一样（每步 ≤ 2 行） | 和好友房一样 |

- **占名额失败的人**：`has_room`（他已经有一个在打的房间）在入队前就挡了，页面直接带他回那个房间；
  `daily_limit` 的人这次不进桌，排队 DO 给他发 `{ t: 'solo', why: 'daily_limit' }`，页面说"今天联机局数用完了，先和电脑打"，其他人照常凑。
- **联机忙**（计量说 `busy`，或者连不上）：整队人都收到 `solo`，页面转单机，说"联机人多，先和电脑打"。不开新房这条和好友房一致。
- 入站、重连、寿命、单连接令牌桶：房间里全部沿用（4.6）。排队 DO 每次请求都计费，所以页面只建一条排队连接、不轮询；推送只在人数变了、或倒计时过半时各发一次，不每秒推。
- 资源总账：匹配桌和好友房都记在本游戏的 `stopWrites` 里（4.7 的表），不另分额度。

## 5. 陌生人：聊天、屏蔽、举报

快速匹配排到的是不认识的人，和好友房（互相给过房间码）不一样，边界这样定：

- **能看到什么**：别人只看到昵称和头像字（和好友房一样）；不给 userId、好友码、用户名。牌桌上没有"加好友"（第一版不做）。
- **快捷短语、表情、道具**：照常（预设的内容，不会冒犯人）；"屏蔽他 / 全部屏蔽"照常，本地生效、对方不知道（`table-fun`）。
- **打字聊天默认关**：
  - 游戏设置里加一项"和陌生人打字聊天"（默认关；好友房的"聊天"开关不变）。存在游戏自己的存储里（`<id>.` 前缀）。
  - 开关关着时，页面进匹配房间就不带 `chat=1`：现有机制下房间不给这条连接转发聊天，自己也发不了，聊天页显示"陌生人桌没开打字聊天（设置里可以开）"。
  - 两个人都开了才互相看得到。房间、过滤、限速全部沿用 `chat.md`，kit 房间这一层**不用为匹配改聊天代码**。
  - 理由：陌生人之间打字最容易出事（骚扰、引流），默认关风险最小；过滤已经挡了链接和号码，开了也只能聊 30 个字。
- **平台屏蔽名单**：
  - 生效方式是"屏蔽过的人排不到一桌"：排队 DO 凑桌前调平台 RPC `ARCADE.blockedAmong(userIds)`（`chat.md` 第 6 节同一个 RPC，只读、读几行），
    有屏蔽关系的两个人不放进同一桌（后来的那个留在队里继续等）。
  - 平台没有这个 RPC（旧平台、单独部署）就跳过，只剩牌桌上的本地屏蔽。**这一条需要平台出 RPC**，顺序请主线定；建议 kit 先留口子（和聊天的 B 方案一样），平台出了 kit 小版本接上，游戏不用改。
  - 牌桌上"屏蔽他"同时写进平台屏蔽名单（以后不再排到）：要平台再出一个按房间座位屏蔽的 RPC（页面拿不到对方 userId，只能经房间转），**第一版不做**，先只有本地屏蔽。
- **举报**：第一版不做。聊天不落库（`chat.md` 第 4 节），没有能举证的记录；先靠"打字聊天默认关 + 屏蔽"。以后做的话要先定记录保留多久、谁来看，再动存储。
- **实盘档**：钱包和好友房实盘一样走房间的 `perform`（每人一份、只结回一次），陌生人之间筹码只在牌局里输赢，不能转让（`economy.md`）。

## 6. 分工

**kit（0.19.0，一个 PR）**
- `src/match.ts`：`MatchQueue` 基类（DO，依赖 `cloudflare:workers`，不进浏览器包）：排队、闹钟、凑桌、调计量和 `kitCreateMatch`、推 `waiting` / `matched` / `solo`。
- `src/worker.ts`：`acceptMatch(request, env, opts)`（和 `acceptJoin` 一样认人、查 Origin、计量连不上时 fail-closed，回 `solo` 而不是报错）。
- `src/room.ts`：`kitCreateMatch`、`match` 房间的预定座位、自动开打（`matchJoinMs`）、不接受外人入座。
- `src/client.ts`：`MatchClient`：`start(tier)`、`cancel()`、`onWaiting(n, leftMs)`、`onMatched(code)`、`onSolo(why)`；断线不重连（直接 `solo`，排队不值得重连）。
- `src/protocol.ts`：排队的上下行消息、`solo` 的原因码。协议只加不改。
- 测试：排队 0 行写入、闹钟只往早挪、满桌立刻开、15 秒 ≥2 人开 / 1 人 solo、`daily_limit` 的人单独 solo、`busy` 全队 solo、同人顶替、每小时入队上限、
  预定座位外的人坐不下、20 秒没到的座位电脑补、有 `blockedAmong` 时屏蔽的两人不同桌（假平台）、没有时跳过。改房间的几条照例反证。
- README、本文、`docs/platform-backend.md` 第 4 节加一行"匹配桌"（主线改根文档或交我一起改，按主线安排）。

**每个游戏（各自一个 PR，kit 发 npm 后）**
- `worker/`：导出一个继承 `MatchQueue` 的类（填 `seats`、档位列表、可选 `matchSeats`、`waitMs`）；`wrangler.jsonc` 加 DO 绑定 `MATCH` 和迁移（`new_sqlite_classes`）；路由 `/match` 接 `acceptMatch`。
- 页面：选档页加"快速匹配"、排队界面（人数、倒计时、取消、不等了）、收到 `matched` 用现有 `RoomClient` 进房（藏起房间码、邀请、叫人）、收到 `solo` 转本机单机（同档位）。
- 设置：加"和陌生人打字聊天"（默认关），匹配房间按它决定带不带 `chat=1`。
- 档位：只开放已经有单机的档位（`solo` 要能接住）；某档单机不支持实盘的，这一档的 `solo` 改成"现在没人，过会儿再来"，由游戏决定。
- 冒烟：两个浏览器上下文同档排队 → 同一桌；一个人排 15 秒 → 转单机。

**平台**：`ARCADE.blockedAmong(userIds)` RPC（和聊天共用，见第 5 节）；大厅以后可以显示"现在有人在排"，第一版不做。

## 7. 第一版不做

- 按水平匹配（段位、ELO）、跨档位或跨游戏凑桌、"任意档位都行"。
- 中途加入别人在打的匹配桌、匹配桌旁观、匹配桌里换人补真人。
- 牌桌上加陌生人好友、"屏蔽他"写进平台名单、举报。
- 排队时一边玩单机、排到了再切过去；排队推送通知（"有人在排"）、大厅显示排队人数。
- 每个档位多个排队实例（一天几个人用不上；人多了再按 `idFromName('<档位>:<分片>')` 分）。
- 同一个人跨档位只排一个（名额管住上限，第一版接受）。

## 8. 待主线定

1. 15 秒是否合适（游戏可调，kit 默认 15 秒）；只剩自己时转单机，还是开一个"一人 + 电脑"的联机房间（转单机不占额度，建议转单机）。
2. 陌生人打字聊天默认关（建议）还是默认开。
3. `blockedAmong` 的先后：kit 先留口子（建议，同聊天 B 方案），还是等平台 RPC 一起上。
4. 先接哪个游戏（建议掼蛋，所有者要和人打；德州、麻将随后）。
