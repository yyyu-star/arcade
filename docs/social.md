# 社交：让人愿意叫朋友来、比得起来、还想再来（所有游戏和平台共用）

> 目标：让朋友玩的意愿更多；做了就要是那回事。注册照旧（邀请制，管理员开关）。
> 这份是**行为规范和分期**：每一项写清楚做成什么样、谁做、怎么验收、为什么这样取舍。两期的功能都已实现（平台的 `presence`、`invites`、`feed`、`challenges`、`mates` 等接口，kit 的 `arcade-kit/share`、`arcade-kit/social`）；
> 接口细节在 [platform-backend.md](platform-backend.md)，共用的浏览器部件在 `packages/arcade-kit`，和牌桌互动（[table-fun.md](table-fun.md)）一样，游戏只接线。

## 0. 底线（每一项都守）

- **不碰真钱、筹码不能送**：社交里的奖励只有称号、头像框这类不影响输赢的东西；不做送筹码、借筹码、圈内奖池（[economy.md](economy.md)）。
- **只给好友看**：在线状态、动态、搭子战绩只对好友可见；每项都能在"我的"里关掉，关了就谁都看不到。
- **不收自由文字**：动态、邀请、颁奖的文字全部来自模板（游戏和平台写死的句子 + 数字 + 名字），玩家不能发自由文字，所以不需要审核。昵称照旧走平台校验。
- **省写入**：D1 每天的写入额度全站共用。每项都写清楚"一个人一天最多写几行"，超了静默丢弃，不报错给玩家。
- **没登录、单独部署时整个不出现**：kit 的社交部件只在 `detectPlatform` 说有平台、且已登录时挂上。

## 1. 第一期：拉得动人（先做）

### 1.1 分享卡（kit `arcade-kit/share` + 每个游戏接）

- 每个游戏的结算页（单机一局 / 实盘一场 / 好友房一场 / 每日挑战）有一个"分享"按钮，生成一张 **1080×1350 的战绩图**（Canvas 画，不经服务器）：
  游戏名和图标、一个大数字（守了多久、赚了多少、名次）、两三条小数据、一句名场面（模板）、玩家昵称和称号、日期。底色按游戏主题色。
- 点"分享"：支持 `navigator.share` 带文件的（手机）直接调系统分享；不支持的出预览，"保存图片"和"复制链接"两个按钮。
  链接是游戏地址，好友房结算带房间码（已经结束的房间打开就是游戏首页）。
- 游戏只交数据：`{ game, title, big: { value, label }, stats: [{ label, value }]≤3, line, accent, art? }`，画法统一在 kit，各游戏风格一致。
- 不上传、不写库，0 行。验收：每个接入的游戏各出一张图，手机和电脑都能存图；图上没有别人的隐藏信息（德州没摊的底牌不画）。

### 1.2 好友在线（平台）

- 好友列表每人一行显示：在线（绿点）/ 几分钟前 / 几天前，在线的显示**在哪**："在掼蛋房里 · 3/4 人"、"在玩开盘"、"在大厅"。
- 浏览器每 **2 分钟**报一次"我在哪"（kit 部件，页面在前台时才报），平台把 `where` 和时间记在用户行上：一个人一天最多 720 次、实际按在线时长，
  跟着 `last_seen_at` 一起写（不另开表）。房间人数由游戏页带上来（它本来就知道），平台不去问房间。
- 超过 5 分钟没报算离线。"我的"里能关掉"让好友看到我在哪"，关了只显示"几天前来过"。
- 验收：两个账号互为好友，A 进掼蛋房，B 的好友列表 2 分钟内看到"在掼蛋房里"；A 关掉开关后 B 看不到位置。

### 1.3 一键叫人（平台接口 + kit 提示条）

- 好友在房间里时，列表那一行有"加入"：直接打开 `/games/<id>/?room=<码>`，房间满了或开打了就进去旁观（1.4）。
- 我在房间里时，好友列表每个在线好友后面有"叫他来"：平台记一条邀请（谁、哪个游戏、房间码、10 分钟有效），每人每天最多 50 条、同一个好友 1 分钟最多 1 条。
- 收邀请：kit 部件在任何游戏页和平台页每 **30 秒**问一次"有没有给我的邀请"（只读），有就在顶上弹一条"老王叫你来掼蛋 [去] [不了]"，
  点"去"跳房间，点"不了"或 10 分钟过期就不再弹。平台首页的好友入口带红点。网页没开着的人下次打开时看到还没过期的邀请。
- 不做系统推送（Web Push 要安装成主屏应用，iOS 上很多人不会装，做了也收不到）。
- 验收：A 开房点"叫他来"，B 正在玩开盘，30 秒内顶上弹出邀请，点"去"坐进 A 的房间；B 在屏蔽名单里的人发不出邀请。

### 1.4 观战（kit 已有底子 + 每个牌桌游戏接）

- kit 的房间本来就让没入座的连接收"公开视图"（座位 -1：只有公开信息），而且没入座的连接单独封顶。游戏要做的是**界面**：
  进房时座位满了、或已经开打，就进"旁观"模式：看得到桌面、出牌、分数、互动，看不到任何人的手牌；顶上写"旁观中"，有空座位时出"坐下"。
- 旁观的人能扔表情和道具吗：不能（kit 现在就是 `not_seated`），只能看。每个房间最多 6 个旁观（kit 封顶照旧）。
- 实盘房间也能旁观（只看，不能带入）。德州摊牌前的底牌、麻将的手牌、掼蛋的手牌一律不下发给旁观的——这条以各游戏的 view 过滤为准，安全审计在查。
- 验收：A、B、C 和电脑开打后 D 用链接进来，D 看到牌桌但没有任何人的手牌；有人离座后 D 能"坐下"接管（照 kit 的座位绑人规则）。

### 1.5 好友周榜（平台）

- 排行榜页每个榜多一个"好友"标签：只列我和我的好友，按本周（北京时间周一 0 点起）最好成绩排。用现有的分数表按好友名单查，**不新增写入**。
- 好友超过我的周成绩时，下次打开平台首页看到一条"老王超过了你的守夜纪录 [去挑战]"（读的时候比较，不另存）。
- 验收：两个好友各交一个分，好友标签里两人都在、顺序对；非好友不出现。

## 2. 第二期：比得起来

- **好友动态**（平台）：好友的名场面按模板生成一条动态。来源两处：①实盘结回时平台已经收到的战绩小结（`stats`，5.10），平台自己生成"老王在掼蛋小档赢了 1.6 份，称号：双下王"，游戏不用改；
  ②娱乐的名场面由游戏页调一个新接口报（只报编号和数字，文字由平台按模板拼），每人每天最多 10 条。动态只给好友看，保留 7 天。
  好友能点"赞"或扔一个道具（用 table-fun 的道具图标），每条每人一次。验收：两个账号走一遍报、看、赞；第 11 条静默丢弃。
- **结束颁奖**（各游戏）：好友房一场结束时按公开数据评"本场 MVP"、"最惨的人"、"最会嘲讽"等 2–3 个奖，配分享卡。
- **异步挑战**（先开盘、夜巡）：结算页"发给好友挑战"，把这一局的种子和设置做成链接；好友打开就是同一个开局，两人的成绩挂在同一个挑战下互相看得到。
  靠规则核心的确定性，不需要服务器重算；每个挑战一行，结果每人一行。
- **搭子战绩**（平台 + 有好友房的游戏）：好友房结回时游戏把同桌真人的 id 带进战绩小结，平台按"我和他"累计场数和输赢，好友页显示"一起打了 23 场"、"最佳搭档"。

## 3. 暂不做（以及为什么）

| 想法 | 不做的原因 | 以后什么时候再看 |
|---|---|---|
| 牌友圈（群、圈内榜、常驻房间、约局） | 现在是邀请制、人不多，好友名单基本就是一个圈；约局到点提醒离不开系统推送，iOS 上收不到；做了大半功能和好友重叠 | 用户多到好友名单装不下、或开放注册以后 |
| 系统推送（Web Push） | 要装成主屏应用才收得到，iOS 上大多数人收不到，做了不是那回事 | 开盘、夜巡的"添加到主屏幕"用的人多了以后 |
| 评论（动态下面留言） | 要审核，公开仓库和小团队扛不住 | 不做 |
| 好友房自定义规则 | 实盘房间改规则会打破配平（[balance.md](balance.md)）；娱乐房间可以做，放进各游戏自己的排期 | 各游戏自己定 |

## 3.1 牌桌聊天

自由文字聊天怕审核扛不住，所以只做**牌桌上的打字聊天**，靠场景把风险收小：

- **好友房**：桌上都是互相给过房间码的人（熟人），说的话发给同桌和旁观的人；旁观的人能看不能发。
- **单机也有**（功能要通用，也要能自己测）：只在本机显示自己说的，冒在自己座位上；过滤、限速和好友房一样（kit 的 `localChat`）。电脑不读聊天，不因为聊天改变打法（公平）。
- **短、慢、可屏蔽**：一条最多 30 个字；服务端限速（每人 3 秒 1 条、每分钟 10 条）；复用现有的"屏蔽这个人 / 全部屏蔽"，平台的屏蔽名单也生效。
- **挡导流**：链接、手机号、微信 / QQ 号样式直接拦下；常见脏话打码。不做人工审核。
- **不留痕**：不落库、不进录像、不进动态，房间关了就没了；服务端只转发，不记内容。
- 形式：现有短语 / 表情 / 道具之外加"打字"，座位冒气泡 + 可展开最近 30 条。
- 做法：kit 做协议、房间转发、过滤、界面（设计写在 `packages/arcade-kit/docs/chat.md`），牌桌游戏好友房和单机（`localChat`）都接上。夜巡、开盘没有牌桌和同桌的人，不接。

## 4. 分工和顺序（做新项时照这个顺序）

1. 平台：1.2、1.3 的接口和好友页、1.5（一个 PR 一项，先接口后界面），接口写进 platform-backend.md。
2. kit：`arcade-kit/share`（1.1）和 `arcade-kit/social`（报位置、收邀请提示条），和平台接口同时开工，按这份文档的形状写；做完主线发 npm。
3. 各游戏：接分享卡、接 social 部件、牌桌游戏做旁观界面；飞驰由它的作者决定。
4. 一期的验收走完之后再开下一期。

## 5. 验收（"做了就要是那回事"）

- 每一项的"验收"一条，维护者用两个测试账号在线上实际走一遍，全过才算这一项完成。
- 写入估算写进 platform-backend.md：按 50 个活跃用户、每人每天在线 2 小时算，第一期每天新增写入不超过 1 万行。
- 隐私开关逐个验证：关了以后好友那边确实看不到。
