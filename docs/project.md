## 0. 一句话

**一个打开网页就能玩、能和朋友一起玩的中文小游戏平台**：每个游戏一局十几二十分钟，好玩、好懂、热闹；
平台负责账号、好友、存档、排行和联机，游戏只管好玩。

## 1. 是什么，不是什么

| 是 | 不是 |
|---|---|
| 一组精做的小游戏，每个都能单独拿出来玩 | 游戏数量取胜的大杂烩、换皮合集 |
| 网页优先：手机横屏和电脑都能玩；目标是微信里点开就能玩（没有备案的域名可能被微信拦截，待实测） | 需要下载安装的客户端（个别游戏另出桌面版除外，见第 6 节） |
| 能单机，也能和朋友一起玩（好友房、同局比拼、排行） | 陌生人社交、聊天室 |
| 游戏为主、娱乐为主，题材可以来自现实（炒股、打牌） | 教学软件、炒股工具、赌博 |
| 积分和成就只是好玩 | 能充值、能兑换、能转让的虚拟货币 |

## 2. 给谁玩

- **主要玩家**：国内的普通玩家，用手机和电脑，常在微信里打开链接；不熟悉游戏术语。
- **典型场景**：碎片时间单机玩一局；和朋友、家人约着打一局牌；把"我今天赚了多少"发到群里比一比。
- **受众（已定）**：第一阶段先给朋友圈子内玩，做稳了再考虑面向公众推广。朋友圈子意味着邀请制（账号由管理员或邀请码发放，注册默认关闭），审核和费用防护也按"小范围、不被刷"来做。

## 3. 产品原则（所有游戏和平台都遵守）

1. **好玩第一**：真实性、学习价值都只为趣味服务。拿不准的改动先问：会不会更难懂、更严肃？
2. **一眼看懂**：中文大白话；能用图标、数字、颜色、动画表达的不写长句；删掉的文字要有更好的表达替代，不能变空。
3. **短局、有反馈**：一局十几二十分钟；每一步都有即时反馈，平淡的地方要快进。
4. **热闹、友善**：电脑对手有性格、有台词；真人和电脑一眼分得清；不嘲弄真实个人，伤亡和政治军事冲突不拿来搞笑；真实公司、商标用化名。
5. **手机友好**：手机横屏能看清、点得中；首屏快，资源轻。
6. **不碰真钱**：不卖虚拟货币、不设现金或实物奖品、积分不能兑换或转让；装饰类（头像、口头禅、特效）免费获得。
7. **公平**：电脑不看别人的牌；联机服务端说了算，不下发别人的隐藏信息。排行榜**不防作弊**（能作弊算玩家自己的本事），只防刷额度、查数据合法性（platform-backend.md 9.2）。
8. **尊重玩家**：不收集不必要的个人信息；能注销并删除数据。现在实行邀请制，只给受邀的朋友玩，不登录不能玩游戏：账号由管理员建，或凭邀请码注册，公开注册默认关闭。以后要公开时，再由维护者决定开放注册。
9. **干净的素材和凭证**：素材只用程序生成的，或许可明确可商用的，来源写进模块说明；凭证不进 Git、不打印。
10. **安全的社交**：动态、邀请这类内容全部来自模板；牌桌上可以打短句聊天，但限长、限速、过滤导流内容、不留痕，可以屏蔽（[social.md](social.md) 3.1）；昵称过敏感词，不许用电脑人物的名字（免得冒充电脑）。

## 4. 游戏阵容与选题标准

| 游戏 | 一句话 | 联机形态 |
|---|---|---|
| 《开盘》`games/kaipan` | 散户的一年：看群聊、追风口、还月供的股市肉鸽，行情来自真实历史；娱乐短局、实盘（含杠杆档）、每日挑战 | 每日挑战排行（不做实时同场） |
| 《牌馆》`games/guandan` | 掼蛋（两副牌四个人，对家一队打到过 A）和斗地主（三人叫分抢地主） | 好友房间码实时（掼蛋 4 人、斗地主 3 人），人不够电脑补位；快速匹配 |
| 《德州扑克》`games/texas` | 无限注德州，2–9 人，电脑性格各异 | 好友房间码实时，空位电脑补 |
| 《雀馆》`games/mahjong` | 一套引擎多种玩法：川麻·血战到底和立直麻将（半庄 / 东风） | 好友房间码 4 人实时，人不够电脑补位；快速匹配 |
| 《夜巡》`games/yexun` | 幸存者类动作：道士夜巡雪夜古镇，只管走位，守夜 / 夜探两个模式，有每日挑战 | 单人；排行和挑战 |
| 《飞驰》`games/racing` | 回合制卡牌赛车（社区贡献者的游戏），只有娱乐模式、不碰钱包 | 好友房间码 2–6 辆，空位电脑补 |
| 《弹里个弹》`games/danli` | 回合制抛物线对战，萌宠和厨房道具大乱斗（社区贡献者的游戏）；第一版单机 1 对 1 打电脑，只有娱乐模式、不碰钱包 | 单人；好友房计划在后续版本 |

除飞驰、弹里个弹外，其余游戏都有娱乐和实盘两种玩法（夜巡、开盘的实盘按各自规则）。各游戏的当前版本和进展以各自的 `package.json` 和 `CHANGELOG.md` 为准。
难度和收益怎么配平见 [balance.md](balance.md)，牌桌互动见 [table-fun.md](table-fun.md)。

**新游戏的选题标准**（满足大部分才立项）：
- 规则一两分钟能讲清，一局 ≤ 20 分钟；
- 单机就好玩，和朋友一起更好玩；
- 国内玩家有共鸣的题材，能做出热闹感；
- 美术和音效能程序生成，或用许可明确可商用的素材；
- 规则核心能写成纯函数、确定性（同种子同操作同结果），这是存档、回放、排行、联机的基础。

## 5. 平台提供什么

| 能力 | 用途 | 状态 |
|---|---|---|
| 游戏目录 | 首页列出游戏、封面、介绍，点进即玩 | 已上线 |
| 账号 | 用户名 + 密码，建号时给恢复码（忘了密码靠它找回）；邀请制：公开注册默认关闭，管理员建号或发邀请码；不登录不能玩游戏；登录后换设备不丢进度；1 年没登录的账号连同云存档删除（管理员账号除外）。邮箱验证码作为第二种找回方式还没做 | 已上线 |
| 云存档 | 各游戏的档案、战绩、教程标记跟着账号走；打到一半的那一局和设置不同步；本地优先，登录后同步 | 已上线 |
| 好友 | 好友码 / 链接加好友、屏蔽；在线状态、一键叫人、好友周榜、好友动态、挑战、搭子战绩（[social.md](social.md)） | 已上线 |
| 排行榜 | 简单版：游戏直接交分，每人每榜留最好成绩，全站榜和好友榜，每日榜 60 天后删；不防作弊、不重放，所以不需要付费版 | 已上线，有每日挑战的游戏接入 |
| 钱包 | 一个钱包，娱乐 / 实盘，同一张档位表（[economy.md](economy.md)） | 已上线 |
| 联机房间 | 房间码开房、电脑补位、断线托管、座位绑人、旁观、快速匹配、每天的额度（kit 提供，房间在各游戏自己的 Worker 里） | 已上线 |
| 费用防护 | 自计量熔断，到线就停，不会意外花钱 | 已上线 |

接口都在同域 `/api/*`，游戏通过它使用平台能力；游戏之间互不依赖（AGENTS.md 第 1 节）。

## 6. 钱：成本和收入

- **成本**：Cloudflare（免费版为主）；也可以自托管，不依赖 Cloudflare（[architecture.md](architecture.md) 第 6 节）。排行榜是简单版、不重放，不需要付费版；
  Workers 付费版（每月 5 美元）在联机或对外开放前开，现在唯一的硬理由是登录的密码哈希：线上登录一次 CPU 39–55 ms（实测），超过免费版的 10 ms，免费版目前放行但没有承诺（platform-backend.md 第 14 节）。
  自计量熔断按 8 美元停服设计，保证每月花费不超过约 10 美元（platform-backend.md 第 6 节）。仓库公开，标准运行器的 Actions 不计分钟；分支保护（main 只经 PR、必须过独立性检查）已开启。
- **收入（待确认）**：早期定过的方向是《开盘》以后出桌面版（用 Tauri，不用 Electron）在 Steam 买断、网页版做试玩（见 `games/kaipan/docs/plan-0.3.md`），目前没有重新确认。平台本身和其他游戏怎么赚钱还没定。
  无论哪种方式，都不违反第 3 节第 6 条"不碰真钱"：不卖虚拟货币、不做抽奖、不设兑换。
  推荐：现阶段先把游戏做好玩、把朋友圈子玩起来，收入方式等有稳定玩家后再定。

## 7. 技术基线（详见 architecture.md）

- 一个总仓库、多个独立模块：`platform/`、`games/<id>/`、`packages/<name>/`，每个都能单独部署、随时拆成独立仓库。
- TypeScript + Vite，Node 22；平台界面 React，游戏按类型选渲染层（开盘、掼蛋、夜巡用 Phaser）。
- 跑在 Cloudflare（Workers 管页面和接口、D1 管账号好友存档成绩、Durable Objects 管联机房间），也可以用 `packages/arcade-host` 和 `tools/selfhost` 自托管。
- 同一个站点主机名（不写在仓库里，部署时由 `production` 环境的 secret `SITE_HOST` 注入），平台在 `/`，游戏在 `/games/<id>/`；浏览器存储一律加 `<游戏id>.` 前缀。
- Worker 数量原则：线上只有平台 1 个（`arcade`）加每个游戏 1 个（名单在 `tools/workers.json`），以后每加一个游戏才多一个；
  **不建任何测试或实验 Worker**，也没有 staging。验证靠本地测试、PR 上的 CI，以及在正式站点上"暗上线"（接口先上、入口藏在开关后面，验证好再打开）；
  出事靠熔断、紧急开关和往前修（platform-backend.md 第 8 节）。联机房间（DO）放在对应游戏自己的 Worker 里。

## 8. 怎么做事

- **流程**：所有改动走 PR，CI 全绿、独立审阅、修完再合并，合并后由维护者批准部署，再到线上验证（CONTRIBUTING.md）。
- **分工**：一个模块同一时间只由一个人写；跨模块的改动（改共用包，或改平台接口同时改游戏）拆成几个 PR 按顺序做，由维护者统筹审阅、合并和发布。
- **验证**：规则用单测，数值和电脑策略用机器人模拟，画面用无头浏览器冒烟截图并亲自看，上线后到线上实际打开。
- **记录**：设计和决定写进仓库文档；每个游戏有自己的 `CHANGELOG.md` 和版本号。
