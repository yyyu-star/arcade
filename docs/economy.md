# 筹码体系：一个钱包，娱乐和实盘两种玩法

> 2026-10-15 定稿，重点是保持娱乐、快乐为主。
> 方案：一种筹码，各游戏分"娱乐 / 实盘"，三个游戏用同一张档位表对齐尺度，再用任务、等级、周榜、装饰把游戏串起来。
> 本文是跨模块的正本，平台和各游戏的实现以本文为准；接口细节写在 `docs/platform-backend.md`（钱包一节随平台 PR 补）。

## 0. 底线（先于一切数值）

- **娱乐、快乐为主**。数值往"好玩、有起伏、输了也不难受"调，不往"刺激、上头"调：
  - 最多输掉带进去的那一份，永远不会欠；
  - 输光了每天有补给，任何时候都能接着玩；
  - 娱乐模式永远免费、不碰钱包，想放松就放松；
  - 不做连续登录惩罚、限时抢购、倒计时催促、"再来一把就回本"这类诱导设计。
- **不碰真钱**（`docs/project.md` 第 3 节、`docs/platform-backend.md` 第 10 节）：筹码只能在游戏里用，没有任何现金价值，不能买、不能兑换、不能在玩家之间转让或赠送，不设奖品。
  牌桌上的输赢就是打牌本身，不算转让。界面写明"无任何现金价值"，隐私说明已写（平台 0.8.2）。
  管理员能在大厅手动给人加减筹码（平台 0.9.4），这只是管理员的手动调整，不是买卖，也不是玩家之间转让。
- **不防作弊**（2026-10-14 定），只防"一个人把体系刷崩"：浏览器里算结果的实盘模式有每日上限（第 4 节）。
- **模块独立**（`AGENTS.md` 第 1 节）：钱包在平台，游戏只通过平台的公开接口用它；游戏之间互不认识。拆出去的游戏换回自己的钱包实现即可。

## 1. 两种模式

| 模式 | 碰不碰钱包 | 是什么 |
|---|---|---|
| 娱乐 | 不碰 | 各游戏原来的玩法：开盘原模式、掼蛋单机和好友房、德州练习桌。随便玩，不算筹码 |
| 实盘 | 进场从钱包带一份，散场按结果结回 | 有输赢的真实感；最多输掉带进去的那一份 |

各游戏的选桌（开局）页用同一个样子：先选"娱乐 / 实盘"，实盘再选档位。钱包连不上、或者今天的联机额度满了时，实盘不可选，娱乐照常。

## 2. 档位表（三个游戏共用，尺度靠它对齐）

| 档位 | id | 一份 | 进场要求 |
|---|---|---|---|
| 小 | `small` | 2,000 | 余额够这次带入 |
| 中 | `mid` | 10,000 | 余额够这次带入 |
| 大 | `big` | 50,000 | 余额够这次带入 |
| 豪华 | `lux` | 200,000 | 余额够这次带入，且等级达到要求（第 5 节，等级上线前不限） |

每次带入 1 到一份。平台 0.10.2 起去掉了"钱包 ≥ 一整份"：余额不到一份也能带着现有的上桌，短码上桌不影响公平。

对齐的三条原则，每个游戏都要满足，用各自的模拟器量出来写进各自的设计文档：

1. **同一档，一场的输赢在"一份"的量级**：最多输一份；正常一场的输赢大多在 ±1 份以内；一场最多赢 3 份。
2. **一场 15–30 分钟**。
3. **越往上越难**：电脑更强、行情更难；小档"简单合理的打法"小赚，往上逐档变难（德州 P0-4 的量化办法，各游戏照做）。具体的量化目标（小白和普通两个玩家模型、赚多快、多难）见 [balance.md](balance.md)。

各游戏怎么落：

- **德州**：带一份上桌（每档的买入上限就是一份；下限由德州自己定，现在是一份的 1/5，可以少带；同一场里可以补码，每次不超过一份）。规则本身就是这个尺度。
- **开盘（实盘）**：带一份当本金。一年打完，按"最终资产 ÷ 初始资产"的倍数结回，最多 3 倍，破产为 0。档位越高行情越难、群里的消息越真假难辨。
- **掼蛋（实盘）**：带一份进场。每一副按名次计分（双下 3 分、单下 2 分、末游 1 分，输的一队扣同样的分），打满一场（比如 8 副或过 A）结算，输赢都封顶一份。
  每分值多少（初值一份的 1/20，8 副最多 ±24 分，会碰到封顶）由掼蛋的设计用模拟定，目标是第 1 条：大多数场次不碰封顶。

**庄家**：电脑一方的输赢都算平台的，不落到任何人的钱包。单机对电脑时电脑那边是庄家；好友房里电脑座位的输赢也由庄家承担。

## 3. 钱包（平台，第一步就做）

- **一个人一个钱包**，存在平台 D1，一人一行。字段：余额、桌上的筹码（按游戏 + ref 一份一份记：ref、档位、金额、到期时间）、补给日期、当天计数（写入次数；每个游戏的净赢和玩过的最高档）、最近的操作 id、最近到期退回过的 ref。
  同一个游戏、不同游戏都可以同时有好几份在桌上（比如德州单机一桌没离桌，又进了好友房），互不影响（平台 0.9.5 起；之前一个游戏只能一份，进好友房会被拒）。
- **新号送 10,000**（第一次用钱包时建行）；**每日补给**：余额加桌上的不到 2,000 时，北京时间每天能领一次，把余额加桌上的补到 2,000，补进来的都进余额（0.10.2 起；之前要求桌上没有筹码，一小份卡在桌上就领不了）。余额上限 1 万亿。
- **只开三个动作给游戏**，都带 `mode`（`server`：结果由服务端说了算，如好友房；`client`：结果由浏览器算）和操作 id，重复请求只算一次（同德州旧仓库 PR 63 的做法）：
  - 带入 `buyin(userId, game, ref, tier, amount, until, op)`：从余额扣到这个游戏"桌上那一份"。每次 1 到一份；同一个 ref 再带入就是补码（要同一档），加到那一份上，到期时间取晚的；换个 ref 就是新开一份；
  - 结回 `settle(userId, game, ref, amount, op)`：把结果结回余额，清掉桌上那一份；
  - 放弃 `refund(userId, game, ref, op)`：没打就走（比如单机开了桌又关掉），那一份原样退回。
- **到期退回**：每份都有到期时间（游戏给，最长 24 小时），过期后下次碰这个钱包时原样退回，并记下 ref；之后这个 ref 再来结回就拒绝（已经退过了）。
- **只有游戏的服务端能调**：经服务绑定（`WALLET`，指向平台的 `WalletService` 入口）的 RPC，浏览器的 `/api` 里没有带入、结回、放弃这几条路。浏览器只能看钱包和领补给。
- **写入**：每次带入、结回、放弃、领补给、到期退回写 1 行（钱包那一行），被拒、重复的写 0 行；按 `docs/platform-backend.md` 6.6 新开一类"钱包"写入预算，同时登记进 7.2 的写入表。全站进入只读档时，结回和放弃照收，桌上的筹码总要能回来。
- **删号**：钱包行进 7.3 的注销和一年清理批次，测试里断言注销后删干净。

## 4. 每日上限（只防刷崩，不防作弊）

> 补给额、单机每日净赢份数、新号送多少、管理员单次调整上限，0.10.6 起管理员在管理页能随时调（平台 `docs/platform-backend.md` 5.9、15.7），这里写的是默认值。

- 结果由浏览器算的实盘（`mode: client`：开盘、掼蛋单机、德州单机）：**每个游戏每天的净赢最多 10 份**（0.10.2 从 3 份放宽；0.10.6 起管理页可调，见本节开头）。净赢 = 当天这个游戏 client 模式结回的总额 − 带入的总额；"份"按当天这个游戏带入过的最高档算（钱包里记着）。
  结回时超出的部分不进钱包，回话里带上"到顶了"，游戏照常显示结果，页面说清楚"今天这个游戏的进账到顶了"。
- 结果由服务端说了算的（好友房）：不设上限。
- 钱包一天的写入次数上限（防脚本刷）：每人 1,000 次，各游戏合计（0.10.2 从 200 放宽，正常玩碰不到）。到了上限不能再带入和领补给；结回、放弃、到期退回不受限（次数由带入那头管住）。

## 5. 把游戏串起来（第四步做）

- **每日任务**：每天 3 个，跨游戏组合（比如"掼蛋打一副""开盘过一年""德州打 20 手"），奖励筹码；娱乐模式也算，不逼人玩实盘。
- **等级**：玩任何游戏都攒经验（按时长和局数，不按输赢），等级解锁豪华档和装饰。等级只涨不跌。
- **周榜**：比本周筹码净增，每周一清零；另有"本周玩得最多"榜。不比总余额。
- **装饰**：头像框、称号、牌背、牌桌皮肤，靠等级、任务、成就免费解锁（`docs/project.md` 第 3 节第 6 条：装饰免费获得），不拿筹码买，只能自己用、不能转让。
- **个人页**：总筹码、等级、各游戏战绩、成就。

## 6. 筹码的来与去（平台每天统计，涨太快就调）

| 来 | 去 |
|---|---|
| 新号 10,000 | 输给电脑（庄家收走） |
| 每日补给 | |
| 每日任务 | |
| 赢电脑（client 模式每天有上限） | |
| 管理员调整（管理员手动加减，有记录） | 管理员调整（扣的时候） |

去处只有"输给庄家"，所以总量会慢慢涨：靠各档越往上越难、补给只补到 2,000、client 模式有上限来压。周榜比净增、不比总余额，总量涨了也不影响好玩。

平台每天记一次全站筹码总量、各来源和去处的数，管理页能看。
